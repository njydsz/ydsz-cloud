执行摘要

经过 v1 轮次 16 项差距的全面修复（P0×3 + P1×6 + P2×7），PMIS 工作流引擎在核心能力层已达到国内开源引擎第一梯队水平，部分能力（灰度发布、AI 审批辅助、嵌入式审批、Redis join 令牌）形成差异化优势。当前 322 单元测试 100% 通过，76 个 HTTP 端点覆盖完整生命周期。

对标 FlowLong v1.1.15（功能最全的开源审批引擎）和钉钉审批（体验最佳的 SaaS 产品），仍存在 8 项体验级差距，集中在可视化设计器、表单引擎、通知渠道落地和移动端支持 4 个方向。建议下一迭代以"前端可视化 + 通知落地"为核心目标。

SWOT 分析

Strengths（优势）

  • 7+1 表极简设计，零第三方 BPMN 依赖，完全自研可控
  • 76 个 REST 端点覆盖全生命周期，API 完整度领先开源竞品
  • 灰度发布、AI 辅助、嵌入式审批 3 项独有能力
  • Redis join 令牌 + @Version 乐观锁，并发处理更可靠
  • 322 单元测试 100% 覆盖，工程质量有保障

Weaknesses（劣势）

  • 无可视化流程设计器，流程定义依赖 XML/代码
  • 表单引擎仅有字段权限配置，无拖拽设计器和运行时渲染
  • 通知通道（站内/邮件/Webhook）均为占位实现，未真正落地
  • 无移动端适配，无法满足移动审批需求
  • 流程定义无导入/导出能力，跨环境迁移不便

Opportunities（机会）

  • PMIS 项目管理场景天然需要审批流，内嵌优势明显
  • FlowLong/Warm-Flow 设计器可参考但不必依赖，自研可控
  • 钉钉/飞书开放平台 API 可对接，复用 IM 通知渠道
  • AI 审批已有基础（推荐+起草），可深化为智能路由
  • 低代码趋势下，表单引擎可渐进式构建

Threats（威胁）

  • Warm-Flow 8.6K Star 增长快，仿钉钉设计器体验成熟
  • FlowLong 功能覆盖最全，AI 审批企业版已落地
  • 钉钉/飞书审批免费使用，客户可能直接选用 SaaS
  • Flowable 8.0 升级 Spring Boot 4，生态进一步扩大
  • 缺乏设计器的自研引擎在交付演示时说服力不足

剩余差距清单（v2 新识别）

P0

GAP-V2-01：可视化流程设计器

差距描述：当前流程定义通过 BPMN XML 或代码部署，无拖拽式可视化设计器。FlowNodeDO 已有 coordinate 字段存储节点坐标，但缺少前端设计器组件。

竞品参考：Warm-Flow 提供双模式（经典+仿钉钉）设计器 jar 包；FlowLong 有独立 flowlong-designer 组件；钉钉审批可视化设计器体验最佳。

建议方案：基于 Vue 3 + VueFlow（或 bpmn-js）开发 PMIS 流程设计器前端组件，后端已有 updateNodeCoordinate 端点支持坐标持久化。预计 2-3 人周。

优先级理由：设计器是交付演示的第一观感，直接影响客户对引擎成熟度的判断。所有竞品均有，属于"必须有"能力。

P0

GAP-V2-02：表单引擎（运行时渲染）

差距描述：FlowNodeDO 已有 formFieldsConfig 字段（JSON 格式字段权限配置），但缺少表单设计器和运行时表单渲染能力。

竞品参考：钉钉拖拽式所见即所得 + 计算公式 + 关联表单；企业微信 15 种控件 + 明细嵌套；飞书控件组 + 显隐条件。

建议方案：分两步走 — (1) 先实现运行时表单渲染器，基于 formFieldsConfig 配置渲染字段权限（EDIT/READONLY/HIDDEN）；(2) 再开发拖拽式表单设计器。可参考 FormCreate/VForm 等开源表单引擎。预计 3-4 人周。

P1

GAP-V2-03：通知渠道真正落地

差距描述：FlowNotificationService 的 IN_APP / EMAIL / WEBHOOK 三个通道目前仅日志输出（占位实现），未对接实际消息基础设施。

竞品参考：钉钉站内信（聊天式工作通知）+ 短信 + 邮件三渠道；泛微 E-Message；飞书待办提醒。

建议方案：IN_APP 通道对接 pmis_message 表（消息模块已有）；EMAIL 通道对接 Spring MailSender；WEBHOOK 通道对接钉钉/飞书机器人 Webhook。预计 1-2 人周。

P1

GAP-V2-04：移动端审批适配

差距描述：当前 76 个端点均为 PC 端 REST API，无移动端专属页面或响应式适配。

竞品参考：钉钉离线缓存 + 单手优化；Warm-Flow v1.8.7 设计器适配手机端；JeecgBoot uniapp APP。

建议方案：基于现有 Vue 3 前端做响应式适配，或开发 uniapp 移动端壳应用。优先保证待办列表、审批通过/驳回、抄送查看 3 个核心流程可用。预计 2-3 人周。

P1

GAP-V2-05：审批人自动去重

差距描述当同一审批人出现在流程的多个连续节点时，当前引擎会逐个生成待办，导致重复审批。

竞品参考：钉钉"自动去重"功能 — 同一人处于多个环节时自动合并，跳过中间节点直接由该人一次性审批。

建议方案：在 createTask 方法中增加去重检查 — 若新任务的 assigneeId 与上一已完成任务的 assigneeId 相同，则自动标记 COMPLETED 并推进。预计 0.5 人周。

P2

GAP-V2-06：流程定义导入/导出

差距描述：流程定义只能通过 deploy 端点部署，无法导出为文件或从文件导入。模板库的 importTemplate 仅支持预置模板。

竞品参考：泛微工作流迁入迁出；Flowable BPMN XML 原生导入导出；Warm-Flow JSON 导入导出。

建议方案：新增 exportDefinition(id) 端点返回 BPMN XML + 节点 + 跳转完整定义；新增 importDefinition(xml) 端点解析并创建草稿。预计 1 人周。

P2

GAP-V2-07：电子签名集成

差距描述：审批通过时无手写签名或电子签章能力。

竞品参考：钉钉手写批注 + 电子签名；泛微电子签章；致远物电签一体化。

建议方案：前端集成签名 canvas 组件，审批通过时上传签名图片关联到审计日志。如需合规电子签，对接 e签宝/法大大 API。预计 1-2 人周。

P2

GAP-V2-08：流程模拟运行

差距描述：流程部署前无法预演流转路径，可能导致条件分支配置错误。

竞品参考：Warm-Flow 流程模拟；Flowable 单元测试框架。

建议方案：新增 simulate(flowCode, variables) 端点，使用模拟变量驱动引擎走一遍流程，返回经过的节点列表和条件判断结果，不创建实际实例。预计 1 人周。

结论与建议

核心判断

PMIS 工作流引擎在后端核心能力层已达到国内第一梯队，8 项差异化能力形成技术壁垒。当前最大短板是前端可视化层（设计器 + 表单引擎）和通知渠道落地，这两项直接影响交付演示和用户体验。

优先行动项

  1. 立即启动（P0）：可视化流程设计器 + 表单运行时渲染 — 这是"从能用变好用"的关键跨越
  2. 快速跟进（P1）：通知渠道落地 + 审批人自动去重 — 投入小、见效快、用户感知强
  3. 中期规划（P1-P2）：移动端适配 + 流程导入导出 + 电子签名 — 完善生态闭环

战略定位

不建议引入 Flowable/Activiti 替换自研引擎 — 当前 15 表设计在 PMIS 场景下比 40 表的 Flowable 更轻量可控。应继续深化自研路线，重点补齐前端可视化短板，形成"后端自研可控 + 前端体验对标钉钉"的差异化定位。
