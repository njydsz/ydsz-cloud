一、架构优化

现状评估：自研 micro-kernel 已具备生产可用雏形

当前采用 micro-kernel（ESM 直引 + 快照沙箱） + micro-runtime（内核抽象层） 双核架构，支持：

  • 基于 manifest.json 的 ESM 入口加载（生产）与 dev server 直引（开发）
  • 快照沙箱：mount 前记录 window 键集合，unmount 后恢复新增/修改项并清理事件监听与定时器
  • keep-alive：DOM detach/reattach 复用，避免频繁 mount/unmount
  • 路由同步：history.pushState/replaceState 补丁 + popstate 监听，按 activeRule 前缀匹配
  • 全局通信：内存 pub-sub 的 globalStateAPI，通过 mountProps 注入子应用
  • 错误降级：加载/挂载失败标记 degraded 并渲染重试 UI

这与字节飞书、阿里钉钉等内部同源微前端方案思路一致，但部分实现细节仍需补齐。

1.1 子应用入口未复用 createSubApp 工厂，main.ts 存在大量重复代码 P0
@ydsz/shared-auth 已提供 createSubApp() 工厂（comm/effects/shared-auth/src/create-sub-app.ts），但 9 个子应用的 main.ts 仍全部手写 bootstrap/mount/unmount/setupApp/createAppRouter，每个文件约 150 行，差异仅 basename 与应用名。总计约 1,300+ 行重复代码，且任何全局初始化调整（如新增插件、统一错误边界）需要改 9 处。
以 createSubApp 重构全部 9 个子应用入口：将 rootComponent、routes、guard、basename、onSetup、preferencesOverrides 提取为配置对象，main.ts 缩减至 20 行以内。先在 1 个应用试点，验证独立运行与微前端挂载双路径正常后批量迁移。
1.2 micro-kernel 路由匹配仅支持 pathname startsWith，不支持 hash/函数式 activeRule P0
kernel.ts 中 startRouterSync 仅通过 path.startsWith(app.activeRule) 匹配，所有子应用注册时必须使用字符串前缀。对比 qiankun / micro-app / Garfish 均支持 activeRule: string | RegExp | ((location) => boolean)，当前实现无法覆盖以下场景：hash 路由、动态前缀、多个不连续路径命中同一应用、带参数的路径前缀。
将 activeRule 类型扩展为 string | RegExp | (location: Location) => boolean，在 startRouterSync 中按类型分别匹配：字符串用 startsWith，正则 test pathname+hash，函数直接调用。保持字符串默认行为向后兼容。
1.3 Proxy 沙箱实现完整运行时隔离 已修复
proxy-sandbox.ts 已实现完整的 Proxy 沙箱，通过 Proxy 拦截所有对 window 的读写操作，使子应用在 mount 期间的所有全局修改都发生在 fakeWindow 上，实现真正的运行时隔离。支持 activate/deactivate/cleanup 生命周期，与快照沙箱并存供选择使用。
1.4 globalState 监听支持取消订阅，防止内存泄漏 已修复
kernel.ts 的 onGlobalStateChange 已返回取消订阅函数，子应用 unmount 时自动清理监听器，防止反复切换导致的监听器累积和内存泄漏。
1.5 keep-alive 补充 activate/deactivate 生命周期 已修复
scheduler.ts 的 keep-alive 实现已补充 activate/deactivate 生命周期钩子调用。重新激活时调用 exports.activate()，摘除 DOM 时调用 exports.deactivate()，使子应用内部依赖这些钩子的逻辑（如暂停定时刷新、恢复动画）能够正确执行。
1.6 globalState 文档与实现已统一，敏感数据不上通信层 已修复
已统一修正文档与代码注释，明确 token 通过 @ydsz/shared-auth 的 SecureLS 读取，不通过 globalState 传递。globalState 仅用于跨应用事件广播（如登录态变更事件），敏感数据传播路径已收口。
1.7 micro-kernel 容器支持 HTMLElement / 多容器 已修复
scheduler.ts 中 resolveContainer 已支持 string | HTMLElement，可在 MicroAppConfig.container 中直接传入 DOM 元素，为嵌套子应用和多容器场景提供扩展能力。
1.8 importmap 默认启用自托管 vendor 已修复
application.ts 中 importmap 插件已默认使用自托管模式（selfHostBase），CI 构建流程已集成 sync:shared-deps 脚本，确保 vendor 目录随产物发布，不再依赖公网 CDN。

二、功能增强

现状评估：基础能力具备，工程化配套未跟上

9 个子应用覆盖用户/系统/项目/消息/定时任务/工作流/知识库/规则引擎/AI Agent 全链路。但 OpenAPI SDK 未真正接入业务、Storybook 组件文档空架子、错误监控实际上报链路不完整。

2.1 OpenAPI SDK 生成后未接入业务，契约检测形同虚设 P0
bash/gen-api.mjs 可生成 TypeScript SDK，但各 app 的 api/ 目录仍是手写文件（app.ts/dictType.ts 等），SDK 生成目录与手写 API 并存。后端接口变更时，手写代码不会自动同步，check:contract 只能检测 SDK 是否过期，无法保证业务代码使用最新契约。
制定迁移计划：(1) 确认后端 Swagger/OpenAPI 规范文件来源与刷新频率；(2) 选择 1 个业务子应用（如 system-web）试点，将手写 API 逐步替换为 SDK 调用，手写层仅保留业务编排；(3) CI 中增加 SDK 生成 + git diff --exit-code 强校验，未同步阻断合并。
2.2 error-monitor 实际上报链路完整 已修复
error-monitor.ts 已实现完整的错误监控链路：Vue errorHandler + window.onerror + unhandledrejection + 资源加载错误捕获。支持采样率控制、beforeSend 钩子、release 版本标识（用于 sourcemap 符号化）、会话追踪（sessionId/traceId）、批量上报、离线缓存、指数退避重试。上报端点为 /api/v1/monitor/error。
2.3 Storybook 组件文档已补齐高频组件 已修复
已为高频组件补齐 Storybook stories，包括 Button、Input、Select、Dialog、Card、Form、Tabs、Loading 等 8 个组件，建立了组件视觉规范。
2.4 错误降级 UI 组件化 + i18n 已修复
error-boundary.ts 已重构为 Vue 组件 MicroAppErrorFallback.vue，支持 i18n 国际化，可通过 MicroAppConfig 注入自定义 fallback 组件。
2.5 统一 retry 策略（含 jitter） 已修复
已在 @ydsz-core/shared/utils/retry 中实现统一的 retryOperation 和 calculateRetryDelay 工具，支持指数退避 + 抖动策略，loader.ts 和 RequestClient 均已接入。

三、性能提升

现状评估：多项基础优化已落地，仍有可提升空间

已做：vendor 三分包、路由全懒加载、静态资源长缓存、多阶段 Docker 镜像、visualizer 分析链路。近期 application.ts 已补齐生产 drop console、Brotli+gzip、es2022 target、chunkSizeWarningLimit 1000 等关键优化。

3.1 引入图片压缩 + 字体子集化 已修复
已引入 vite-plugin-imagemin 和 vite-plugin-font。图片压缩支持 PNG/JPG/GIF/SVG/WebP，字体子集化可将中文字体从数 MB 降至百 KB 级。
3.2 基于菜单 hover/权限动态调整 prefetch 已修复
preload-strategy.ts 已实现完整的预加载策略管理器，支持 idle/hover/visibility/route/permission/frequency 多种策略。包含权限检查、使用频率统计、网络条件感知等能力。
3.3 评估启用 PWA 已修复
vite-plugin-pwa 已启用，配置了 Workbox 策略：应用骨架走 precache，API 请求走 NetworkFirst，静态资源走 CacheFirst。Service Worker 已正确配置 scope 和 CORS。
3.4 requestIdleCallback fallback 已修复
已在 kernel.ts 中实现 scheduleIdle 函数，优先使用原生 requestIdleCallback，不支持时回退到 setTimeout，保证预加载在所有浏览器中正常工作。

四、体验改善

现状评估：基础体验完善，微前端切换体验是短板

已做：nprogress 进度条、标签页拖拽 + keepAlive 缓存、SecureLS 加密持久化、i18n 延迟绑定。但微前端切换白屏、骨架屏缺失、错误边界薄弱等痛点仍存在。

4.1 微前端切换白屏问题 P0
旧应用卸载 → 新应用加载 → 新应用挂载之间存在白屏间隙。虽然有固定 prefetch 缓解首次加载，但已加载子应用切换时仍有可感知的白屏，且 #subapp-container 在切换期间无占位内容。
(1) 在 SubAppContainer 中增加骨架屏/loading 占位，监听 micro-kernel 的 beforeLoad/afterMount 生命周期切换显示状态；(2) 为高频子应用设计专属骨架屏；(3) 对 keep-alive 缓存过的子应用切换时直接复用 DOM，避免白屏。
4.2 统一全局错误边界 已修复
create-sub-app.ts 已统一注入 vueApp.config.errorHandler 和 warnHandler，error-boundary.vue 提供错误降级 UI 展示，error-state.vue 提供重试入口。
4.3 网络异常体验优化（空状态/重试组件） 已修复
error-state.vue 已实现统一错误状态展示组件，支持自定义消息、重试按钮、返回上一页等功能，用于 API 请求失败、网络异常等场景。
4.4 统一 registerLoadingDirective 参数 已修复
已在 createSubApp 工厂中统一调用 registerLoadingDirective，参数标准化为 { loading: false, spinning: 'spinning' }，所有子应用不再手动传参，消除行为差异。
4.5 页面级骨架屏组件 已修复
已实现 5 种页面级骨架屏组件（ListSkeleton / FormSkeleton / DetailSkeleton / DashboardSkeleton / DefaultSkeleton），通过 skeleton-registry.ts 按路由 meta.skeletonType 动态加载，在 SubAppContainer 中集成展示。

五、工程质量补齐

现状评估：规范配置齐全，执行与覆盖率是最大短板

TypeScript 严格模式、ESLint flat config + 18 模块、Stylelint、commitlint、changesets、lefthook 等配置已存在。但 lefthook 是否真正安装到 .git/hooks 需确认，测试无覆盖率门槛，业务应用几乎零单测。

5.1 需确认 lefthook 是否真正安装到 Git hooks P0
lefthook.yml 配置完整且未注释，但 .git/hooks 目录未找到钩子文件。若仅依赖 CI 检测，本地提交前不会执行 lint/type-check/commitlint。
执行 pnpm lefthook install 确保钩子安装到 .git/hooks；CI 中增加 lefthook run pre-commit --force 作为兜底；分阶段启用：commit-msg → pre-commit（staged 文件） → pre-push（type-check）。
5.2 测试无覆盖率门槛，业务应用几乎零单测 P0
全仓约 38 个 .test.ts 文件，主要集中在 comm/@core/base/shared/utils、comm/stores、comm/effects/request、comm/effects/micro-kernel 等公共包，业务应用 apps/* 几乎无单测。vitest.config.ts 中 coverage enabled 为 false，未配置阈值。
(1) 开启 coverage：enabled: true，公共包设定阈值 80% lines/functions/branches，业务包 50% 起逐步提升；(2) 优先补齐 @ydsz/shared-auth、@ydsz/request、@ydsz/micro-kernel 核心路径；(3) CI 中上传覆盖率到 Codecov 或自研平台。
5.3 check-circular 改为 fail 模式 已修复
package.json 中 check:circular 已使用 vsh check-circular --fail 模式，发现循环依赖时会阻断构建流程。
5.4 tsconfig 补充 paths 映射 已修复
已在各应用的 tsconfig.json 中配置 paths 路径别名，与 Vite alias 保持同步，IDE 跳转和类型检查正常工作。
5.5 E2E 测试用例薄弱 P1
Playwright 仅 1 个 core-flows.spec.ts（登录/导航/登出），chromium 单浏览器，断言宽泛，凭据硬编码。
(1) 扩展浏览器矩阵到 chromium + firefox；(2) 凭据改为 process.env.E2E_USER；(3) 补充各子应用核心流 E2E（项目创建/审批流/消息发送）；(4) 断言改用 expect(locator).toBeVisible() 等硬断言。
5.6 CI 缓存优化（pnpm store + turbo cache） 已修复
frontend-ci.yml 已配置 pnpm store 缓存（通过 actions/setup-node 的 cache: 'pnpm'）和 turbo build 缓存（使用 actions/cache@v4 缓存 node_modules/.cache/turbo），显著缩短 CI 构建时间。

6.6 Changesets 已配置 已配置
