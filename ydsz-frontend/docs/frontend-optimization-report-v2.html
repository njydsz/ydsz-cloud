一、架构优化（4 项）

1.1 确立 CSS 样式隔离规范 — 全项目 146 个 Vue 文件强制 scoped P0 · 新增
现状：全项目 146 个 Vue 文件，0 个使用 <style scoped>。所有样式依赖 Tailwind utility class + 全局 SCSS，在微前端多应用共存场景下存在严重的样式污染风险。

行业对标：蚂蚁 Ant Design Pro 强制 CSS Modules，字节飞书微前端使用 Shadow DOM 隔离，Vben Admin 统一 <style scoped>。

风险：随着子应用增多（9 → 可能更多），全局样式冲突概率指数级增长；micro-kernel 的 PostCSS prefix 仅处理构建期，无法覆盖运行时动态样式。
1) 配置 ESLint 规则 vue-scoped-css/enforce-style-type 强制 scoped；2) 对现有全局样式做增量迁移——新增文件必须 scoped，存量文件按月分批改造；3) 对确实需要穿透的样式统一使用 :deep() 语法；4) 考虑引入 stylelint-scss 禁止全局选择器。
参考：Ant Design Pro / Vben Admin 的样式隔离规范；飞书微前端的 Shadow DOM 作为远期演进方向。
1.2 消除 adapter 重复代码 — vxe-table/form 适配器提取为公共包 P0 · 新增
现状：9 个子应用中，adapter/vxe-table.ts 和 adapter/form.ts 各存在 9 份几乎完全相同的副本（仅注释中的应用名不同），合计约 30,000+ 字节的重复代码。

行业对标：Vben Admin 的 useTable 和 useForm 为全局注册，子模块零配置使用；阿里内部 ProTable 作为组件级抽象。

影响：修改一处适配（如 vxe-table 版本升级 API 变更）需要在 9 个应用中逐一改动，极易遗漏导致线上不一致。
1) 在 comm/effects/shared-business 中创建 adapter/ 目录；2) 将 vxe-table 和 form 适配器提取为 @ydsz/shared-business/adapter 导出；3) 各子应用改为 import { createVxeTableAdapter } from '@ydsz/shared-business'；4) 适配器支持参数化配置（翻页大小、日期格式等差异化项）。
参考：Vben Admin 全局组件注册模式；美团到店 schema-driven 表单配置。
1.3 建立 WebSocket/SSE 实时通信基础设施 P1 · 新增
现状：全项目零 WebSocket / SSE 能力。消息通知、工作流审批、定时任务执行状态等需要实时反馈的场景，当前只能依赖轮询或手动刷新。

行业对标：飞书/钉钉微前端通过全局 WebSocket 总线广播消息；企业微信管理后台使用 SSE 推送系统通知；Ant Design Pro 生态有 @umijs/plugin-qiankun 全局事件总线。
1) 在 comm/effects/ 下创建 realtime 模块；2) 封装 RealtimeClient 类（自动重连、心跳、离线队列、跨 Tab 去重）；3) 提供 useRealtime(channel) composable 用于业务层订阅；4) 优先使用 WebSocket，对单向推送（如系统公告）使用 SSE 降低复杂度；5) 集成到 globalState 通信层，子应用通过 onGlobalStateChange 接收实时事件。
参考：字节飞书 WebSocket EventBus；Socket.IO 社区最佳实践（心跳间隔 30s，指数退避重连 max 30s）。
1.4 iframe 沙箱方案增强 — 支持 postMessage 通信协议 P2 · 新增
现状：iframe-sandbox.ts 已实现 iframe 强隔离沙箱，但缺少结构化的 postMessage 通信协议，主-子应用间通过简单的 message 事件传递信息。

行业对标：qiankun 的 initGlobalState 已有成熟的主-子通信 API；iframe 微前端方案（如无界 wujie）的通信协议支持 RPC 调用。
1) 定义标准化的 iframe 通信协议（action + payload + callbackId 格式）；2) 实现 request-response 模式的 RPC 调用（主应用调用子应用方法并获取返回值）；3) 支持结构化事件广播（区别于点对点调用）。
参考：qiankun globalState API；腾讯无界(wujie)的通信设计。

二、功能增强（7 项）

2.1 实现数据字典全局缓存方案 P0 · 新增
现状：dict-select.vue 是一个空壳组件，核心逻辑被注释，只有 TODO 标记。全项目没有任何字典数据缓存，每次页面加载都需要重新请求所有字典数据。

行业对标：Vben Admin 的 useDictStore 提供了按需懒加载 + TTL 过期的字典缓存；美团 CRUD 体系字典数据与表格/表单深度绑定。
1) 实现 useDictStore Pinia store（按 code 分组缓存，支持 TTL 过期）；2) 完善 dict-select.vue 组件，从 store 获取字典数据并支持 dictCode prop 驱动；3) 增加 dict-tag 组件用于表格列字典值渲染；4) 主应用 bootstrap 阶段预加载高频字典（性别/状态/是否等通用枚举）。
参考：Vben Admin useDictStore 实现；Ant Design Pro ProFormDictSelect。
2.2 实现统一 Excel 导入导出方案 P0 · 新增
现状：全项目零 Excel 导入导出能力。企业管理系统中，用户信息批量导入、项目列表导出报表、财务报表导出等功能是刚需。

行业对标：Vben Admin 提供了 ExcelImport 和 ExcelExport 通用组件；阿里内部后台有 @alife/export-excel 统一工具链。
1) 引入 exceljs（样式导出）和 xlsx（轻量导入）；2) 在 shared-business 中实现 useExcelExport composable（支持列映射、样式模板、大数据量流式导出）；3) 实现 useExcelImport composable（模板下载、文件解析、数据校验、错误反馈）；4) 提供声明式组件 ExcelExportButton 和 ExcelImportButton。
参考：Vben Admin src/components/Excel；exceljs 官方流式写入最佳实践。
2.3 接入 OpenAPI SDK — 从手写 API 迁移到类型安全客户端 P1 · 新增
现状：gen-api.mjs 和 createOpenApiClient 基础设施已就绪，但全部 122 个 API 文件仍为手写模式。存在参数拼写错误、类型漂移、接口变更无感知等风险。

行业对标：蚂蚁的 @umijs/plugin-openapi 从 Swagger 自动生成 API 代理；字节内部使用 Protobuf + 代码生成保障前后端契约一致性。
1) 运行 pnpm gen:api 生成各子应用的 schema.d.ts；2) 在 一个子应用试点（推荐 system-web）将 API 迁移到 apiClient.GET/POST 模式，验证工作流；3) CI 加入 pnpm gen:api --check 检测契约漂移；4) 编写迁移脚本辅助批量转换。
参考：@umijs/plugin-openapi 代码生成模式；openapi-typescript + openapi-fetch 社区实践。
2.4 实现统一 CRUD 业务 Hooks 体系 (useCrudTable / useServerPagination) P1 · 新增
现状：全项目缺乏服务端分页 Hook。现有的 usePagination 仅做前端数组切片，无法处理 pageNum/pageSize 请求参数。每个列表页都需要手写相似的分页查询逻辑，导致大量重复代码。

行业对标：Vben Admin 的 useTable 封装了完整的分页请求、查询条件管理、数据刷新逻辑，是业界 Vue 3 后台系统的标杆实现。蚂蚁 ProTable 更进一步——一个组件覆盖搜索/表格/分页/导出。
1) 实现 useServerPagination Hook（pageNum/pageSize 状态 + queryParams 合并 + 自动触发）；2) 实现 useCrudTable Hook（集成搜索/分页/删除确认/批量操作/刷新）；3) 集成 vxe-table 的 proxy-config 自动配置；4) 提供类型安全的泛型支持。
参考：Vben Admin useTable 源码；Ant Design Pro ProTable API 设计。
2.5 增强国际化 — 业务中文硬编码治理 P1 · 新增
现状：框架层（布局/认证/偏好设置）已正确使用 $t()，但99% 的业务页面全部硬编码中文（146 个 Vue 文件），国际化形同虚设，无法实际支持英文用户。

行业对标：蚂蚁国际业务强制 eslint-plugin-formatjs 拦截所有硬编码文案；字节国际化平台自动抽取+翻译+合入。
1) 引入 eslint-plugin-vue-i18n 的 no-raw-text 规则（先 warning 模式，逐步改为 error）；2) 优先迁移高频页面（project-web → system-web → userinfo-web 分批推进）；3) vxe-table 列定义适配 $t() 动态标题；4) 建立翻译词条管理规范（按模块/页面组织 JSON 文件）。
参考：eslint-plugin-vue-i18n no-raw-text 规则；字节 i18n Platform 自动化流水线。
2.6 实现统一操作审计日志组件 P1 · 新增
现状：仅 literule-web 有审计日志功能，其他 8 个子应用完全缺失。在企业管理系统中，操作审计是合规刚需。

行业对标：阿里云控制台的操作审计；腾讯云 CAM 访问管理的审计日志组件。
1) 在 shared-business 中实现 AuditLogTable 通用组件；2) 提供 useAuditLog composable 封装查询逻辑（操作人/操作类型/时间范围筛选）；3) 在 requestClient 拦截器中集成，对 CUD 操作自动记录操作摘要。
参考：阿里云 ActionTrail 审计日志设计；Ant Design Pro 的操作记录组件。
2.7 工作流设计器能力强化 P2 · 新增
现状：workflow-web 已有流程设计器基础能力，但交互体验和高级功能（如决策表可视化、SLA 时间轴、批量审批）可进一步强化。作为 PMIS 系统的核心模块之一，其成熟度直接影响产品的竞争力。
1) 支持键盘快捷键操作节点（Delete 删除、Ctrl+C/V 复制粘贴）；2) 增加迷你地图导航（针对大流程）；3) 支持审批历史时间轴可视化；4) 增加流程模拟/预览功能（无需实际发起即可预览流转路径）。
参考：Camunda Modeler 交互设计；钉钉/飞书审批流设计器。

三、性能提升（3 项）

3.1 实现请求级数据缓存 (stale-while-revalidate 策略) P1 · 新增
现状：每次页面切换都重新请求全部数据，无任何请求级缓存。字典数据、配置数据、菜单数据等低频变更的数据，每次都走完整网络请求链。

行业对标：SWR (stale-while-revalidate) 是 Vercel 推行的数据获取范式，已被 React 生态广泛使用；Vue 生态有 vue-request / @tanstack/vue-query 等成熟方案；Ant Design Pro 5 内置了 useRequest 的缓存能力。
1) 在 comm/effects/request 中增加 cacheAdapter 扩展点；2) 优先对字典/菜单/配置等低频变更 API 启用 SWR 缓存（先返回缓存，后台更新）；3) 支持 TTL + staleTime 配置；4) 可选集成 @tanstack/vue-query 管理服务端状态，与 Pinia 客户端状态分层。
参考：Vercel SWR 策略；@tanstack/vue-query staleTime + cacheTime 设计。
3.2 增加 Bundle 体积持续监控 (Bundle Tracker) P1 · 新增
现状：已有 rollup-plugin-visualizer 离线分析和 bundleBudgetPlugin 硬阈值校验，但缺少时间维度的体积变化追踪。无法直观感知每次 PR 对产物体积的影响。

行业对标：字节内部有自研的 Bundle Tracker 平台；Google Chrome 团队的 bundle-size-action；GitHub 上广泛使用的 bundlesize 和 size-limit。
1) 引入 @size-limit/preset-app 为每个子应用配置体积阈值；2) CI 中加入体积检查步骤，超限阻断合并；3) 生成体积变化报告（HTML），直观展示每个 PR 的体积影响；4) 建立历史数据看板，追踪趋势。
参考：size-limit CI 集成方案；Chrome DevTools bundle-size-action。
3.3 虚拟列表扩展 — 非表格大数据场景 P2 · 新增
现状：依赖 vxe-table 内置虚拟滚动处理表格场景，但对于下拉选择器中的大数据选项（如部门选择 > 5000 条）、树形菜单大数据节点等非表格场景，没有虚拟列表方案。
1) 引入 @tanstack/vue-virtual 作为通用虚拟列表方案；2) 封装 VirtualSelect 组件（大数据下拉选择器）；3) 封装 VirtualTree 组件（大数据树形组件）。
参考：@tanstack/vue-virtual 文档；Element Plus select-v2 虚拟化实现。

四、体验改善（4 项）

4.1 统一空状态 / 加载态 / 错误态设计规范 P1 · 新增
现状：已有 error-state.vue 错误状态组件和骨架屏，但 146 个业务页面中，空状态/加载态/错误态的表现形式完全不统一。有的页面用 v-loading，有的用自定义 spinner，有的直接空白。

行业对标：Ant Design 的 Result + Empty + Skeleton 形成完整的状态展示体系，每个组件的使用场景有明确的设计规范。
1) 设计统一的空状态/错误状态/加载状态视觉规范（含文案模板）；2) 提供 EmptyState / LoadingState / ErrorState 组件（在 shared-business 中）；3) 封装 AsyncState 容器组件，根据 loading/error/empty/data 自动切换展示。
参考：Ant Design Result + Empty + Skeleton 规范；Stripe 前端状态设计模式。
4.2 键盘快捷键体系 P1 · 新增
现状：零键盘快捷键支持。对于高频操作（搜索、新建、保存、刷新列表），用户只能通过鼠标点选。

行业对标：飞书/钉钉的 Cmd+K 命令面板；Notion 的全键盘操作体系；GitHub 的 ? 快捷键面板。
1) 实现 useKeyboardShortcut composable（支持组合键、作用域隔离、冲突检测）；2) 配置文件 keyboard-shortcuts.ts 集中管理快捷键映射；3) 优先实现：搜索（Ctrl+K）、保存（Ctrl+S）、新建（Ctrl+N）、刷新列表（Ctrl+R）；4) 增加 ? 快捷键帮助面板。
参考：GitHub 快捷键系统；Notion Cmd+K 命令面板；飞书快捷键设计规范。
4.3 用户操作引导 (Onboarding Tour) P2 · 新增
现状：PMIS 系统功能模块多（9 个子应用），新用户上手成本高，缺少功能引导。

行业对标：Ant Design Pro 的 @ant-design/pro-components Tour 组件；飞书/钉钉管理后台的新手引导。
1) 引入 driver.js 或 shepherd.js 引导库；2) 在 shared-business 中封装 AppTour 组件；3) 为关键操作流程（首次登录、发起审批、导入数据）配置 Step 引导链；4) 引导状态持久化到 localStorage，已完成用户不再展示。
参考：driver.js 社区方案；飞书管理后台新手引导交互。
4.4 移动端适配基础能力 P2 · 新增
现状：全系统为桌面端设计，但企业中移动审批、移动端查看项目进展等场景日益增多。当前缺少适配基础。

行业对标：钉钉/飞书管理后台的响应式适配；Ant Design Mobile 的 H5 适配方案。
1) 在 comm/@core/composables 中已有 useIsMobile，可利用此基础设施；2) 关键审批/查看页面增加响应式布局；3) 移动端使用独立的 vxe-table 配置（减少列、增大触控区域）。
参考：Ant Design Mobile；企业微信管理后台响应式实践。

五、工程质量补齐（3 项）

5.1 子应用单元测试从零到一 — 建立测试基线与冒烟覆盖 P0 · 新增
现状：全部 9 个子应用测试文件数为 0。仅 comm/stores 有 3 个测试文件。vitest.config.ts 已配置了 70%/80% 的覆盖率阈值，但目前覆盖率实际为 0%（因为阈值通过 perFile: true 只在有测试文件的模块中生效）。

行业对标：Google 前端测试金字塔——大量单元测试 + 适量集成测试 + 少量 E2E + 可视化回归测试。蚂蚁前端强制要求核心模块 80%+ 覆盖率。
1) 为每个子应用的 1 个核心模块 编写冒烟测试（页面渲染/API 调用/核心交互）；2) 优先覆盖：表单校验逻辑、数据转换 util、用户权限判断；3) 使用 @vue/test-utils + vitest 组件级测试；4) CI 中增加 test:unit --changed 增量测试模式（仅测变更文件）；5) 建立测试编写指南文档（含 Mock 最佳实践）。
参考：Vue Test Utils 官方指南；Vben Admin 测试实践；Google 测试金字塔模型。
5.2 ESLint 规则升级 — 补充 i18n + scoped + import 规则 P1 · 新增
现状：ESLint 9 flat config 已配置 18 个插件，覆盖 vue / ts / perfectionist 等，但缺少两个关键质量规则：国际化硬编码检测和 scoped 样式强制。

行业对标：蚂蚁 eslint-config-ali 包含 @typescript-eslint 严格模式 + import 排序 + i18n 检测；字节内部 ESLint 配置包含 eslint-plugin-i18n。
1) 新增 eslint-plugin-vue-i18n 并配置 no-raw-text 规则（PR 范围先 warning）；2) 新增 eslint-plugin-vue-scoped-css 并配置 enforce-style-type 规则；3) 强化 import-x/order 规则，统一导入排序（builtin → external → internal → parent → sibling）；4) 分阶段收紧规则：warning 阶段（1 个月）→ error 阶段（稳定后）。
参考：eslint-config-ali 规则体系；Vue eslint-plugin-vue-scoped-css 文档。
5.3 依赖管理自动化 — 引入 Renovate/Dependabot P2 · 新增
现状：依赖升级完全依赖人工，catalog 统一版本管理的优势在于升级时只需改一处，但缺乏自动化提醒机制。Vue 3.5.17 → 3.6.x、Vite 6.3.5 → 6.5.x 等升级容易被忽视。

行业对标：Google 内部有依赖自动升级机器人；GitHub 生态广泛使用 Renovate 或 Dependabot 自动化依赖更新。
1) 在 .github/renovate.json 中配置 Renovate（支持 monorepo 分组升级）；2) 配置分组策略：patch 自动合并，minor 自动创建 PR，major 人工审核；3) 集成 pnpm dedupe 去重检查。
参考：Renovate monorepo 配置模板；Vue 官方 ecosystem-ci 依赖管理实践。

总结：

ydsz-frontend 的技术定位：自研 micro-kernel 微前端架构 + monorepo 工程化 + 共享认证体系，在行业同类 PMIS 系统中属于第一梯队。v1 报告的 30 项优化全部落地后，架构和性能层面已达到行业头部水平（A 级）。

核心差距不在架构，而在「规范落地」：CSS 零 scoped（样式污染风险）、测试零覆盖（质量风险）、i18n 零使用（国际化失效）、字典零缓存（性能浪费）——这些问题每一项都是大厂代码审查的一票否决项。

建议优先级：第一阶段 6 项 P0（14 天）建立质量基线 → 第二阶段 9 项 P1（28 天+）能力对标行业头部 → 第三阶段 6 项 P2（按需推进）体验致胜。

关键决策点：国际化硬编码治理（2.5）是一个成本较大的持续工程，需团队达成共识——若短期无国际化需求，可降为 P2 仅保留 ESLint 规则不执行迁移；若未来有海外部署计划，则必须 P1 推进。
