## ydsz-common-core 过度设计评估

- **产出**：`docs/YDSZ_COMMON_CORE_OVERDESIGN_ASSESSMENT.md`（完整评估报告，含 4-Sprint 落地路线）
- **方法**：源码全量阅读（18 个实际文件）+ README/配置元数据/编译产物交叉比对 + 行业对标（COLA/Spring Boot Starter/Hutool）
- **核心发现**：
  1. **P0-1 文档漂移**：README 描述 30+ 个类，实际只有 18 个；12 个"幽灵类"（TenantContextHolder、TenantMdcFilter、CoreHealthIndicator、FilterIgnoreProperties、CacheConstants、TypeEnum、DataScopeType、IdentityType、ServiceType 等）实际归属 ydsz-common-base/web/tenant
  2. **P0-2 重载膨胀**：BaseResponse 11 个 success/error 重载，存在 `error(String msg, T data)` 当 T=String 时与 `error(String code, String msg)` 歧义
  3. **P0-3 不可靠 default**：`ResultCode.getHttpStatusCode()` 的 default 推断策略把 A10301 (RATE_LIMIT) 推断成 400，导致 BaseResultCode 必须 override 整个 switch
  4. **P0-4 配置元数据漂移**：metadata 声明 9 个配置，CoreProperties 只有 3 个字段 + 1 开关
  5. **P1-1 设计缺陷**：PageResponse extends BaseResponse 导致 data 语义错位（单值 vs 列表）
  6. **P1-2 半成品抽象**：Sensitive 在 core 但接入点不明确
  7. **P1-3 边界违反**：HeaderConstants 包含 auth/data-scope 业务头常量
- **路线图**：4 个 Sprint（P0→P1→P2→P3），共 6-8 人天
- **记忆**：YDSZ 系列 common 模块（如 core/base/web/auth/tenant）的边界审计应优先做"文档-代码一致性"检查而非"代码风格"审查
