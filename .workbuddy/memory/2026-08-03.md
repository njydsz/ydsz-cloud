## 2026-08-03

### ydsz-common-json 过度设计评估
- 完成 `ydsz-common-json` 模块全面过度设计评估，输出报告 `docs/ydsz-common-json-overdesign-assessment.md`
- **核心发现**：115 文件 / 29,530 行代码，4 个测试。核心序列化（YdszJson）高频使用（140+ 文件），但高级功能（Schema/Path/Patch/Pointer/Merge/Module）几乎零使用，占 ~40% 代码量
- **关键问题**：
  1. ASM 50 倍性能宣称无 JMH 基准数据佐证
  2. 零使用高级功能未拆分为独立可选模块
  3. L2 工具层反向依赖 Spring Boot/Micrometer/Web
  4. 6 级反序列化降级路径 + 3 套注册表 + 2 套树模型
  5. 测试/代码比 = 1:7375
- **建议三阶段**：P0 JMH 基准决定 ASM 去留 + 补测试 → P1 裁撤零使用功能为独立模块 + 收敛架构 → P2/P3 缓存加固 + 文档对齐
- 对比 08-02 分析文档的修复状态：ASM 前缀 bug ✅、死代码删除 ✅、wrapRootValue ✅、HealthIndicator ✅、测试补充 ✅；性能基准、零使用功能裁撤、依赖拆解仍待处理

### ydsz-common-json 全面优化建议
- 完成对标行业主流竞品（FastJSON2/Jackson/Gson）与互联网大厂研发规范的全面分析，输出报告 `docs/ydsz-common-json-优化建议报告.md`
- **核心发现**：
  - 模块在零外部依赖、ASM 双端加速、AutoType 安全（100+ CVE 黑名单）、Micrometer 指标、GraalVM 兼容等维度已达行业领先
  - P0 阻塞项：测试仅 4 个文件（行业标准 200+）、ASM 错误处理使用 System.err（非生产规范）、ThreadLocal 非 Spring 场景泄漏风险
  - P1 竞争力提升：缺少流式大 JSON 处理、二进制 JSON（JSONB/BSON）、JSON Schema 仅 Draft 07、缺 @JsonFilter/@JsonIdentityInfo 等关键注解、Module 扩展机制不完善
  - P2 体验优化：无使用文档、旧 SPI 无迁移指引、API 命名不一致、异常信息可定位性不足
- **分阶段路线图**：P0（测试+日志+安全）→ P1（流式+二进制+Schema+注解+Module+文档）→ P2（命名统一+异常增强+微优化）
