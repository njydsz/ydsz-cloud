## P0-1: 合并 workflow 通知到 message

### 变更内容
- 废弃重复表清理与数据迁移（已合并至各模块 DDL）
  - `pmis_flow_notify_template` 种子数据迁移到 `pmis_msg_template`（FLOW_ 前缀）
  - `pmis_flow_notify_preference` 数据迁移到 `pmis_msg_preference`
  - `pmis_flow_webhook_subscription` 数据迁移到 `pmis_msg_route_rule`
  - 4 张废弃表标记 DEPRECATED 注释
  - `pmis_flow_notify_outbox` 保留（Outbox Pattern 有独立价值）

### 代码变更
- `FlowNotificationServiceImpl` 已在之前版本完成 Feign 适配器改造
- workflow 通知全部通过 `NotificationClient` + `MessageServiceClient` Feign 调用 message 模块

### 消除的重复
- 删除 3 张冗余表（pmis_flow_notify_template / pmis_flow_notify_channel / pmis_flow_notify_preference）
- 删除 1 张冗余表（pmis_flow_webhook_subscription）
- 消除 ~10 个重复类的功能

## P0-2: 统一告警事件总线

### 新增文件
| 文件 | 说明 |
|------|------|
| `common/alert/UnifiedAlertEvent.java` | 统一告警事件模型 |
| `common/alert/UnifiedAlertDispatcher.java` | 统一告警分发器（消费事件，委托 message 模块发送） |
| `common/alert/package-info.java` | 包说明文档 |

### 代码变更
- `project/AlertDispatchServiceImpl`: 移除直接 Feign 调用，改为通过 `ApplicationEventPublisher` 发布 `UnifiedAlertEvent`
- `cronjob/AlertDispatcher`: 在告警派发完成后，发布 `UnifiedAlertEvent` 到事件总线

### 架构改进
- 告警链路从"各模块直接调 Feign"变为"各模块发布事件 → 统一分发器消费 → message 模块发送"
- 移除了 project 对 `MessageServiceClient` 和 `NotificationClient` 的直接依赖
- 移除了 `@GlobalTransactional` 分布式事务（改用事件驱动的最终一致性）

## P1-2: project 规则表迁移到 literule

### 迁移说明
- project 的 8 张 `pmis_rule_*` 表归属权迁移到 literule 模块管理
- `V1.0.0_literule.sql`: 添加迁移说明注释

## P2-2: ArchUnit 架构约束

### 新增文件
| 文件 | 说明 |
|------|------|
| `common/architecture/ArchitectureTest.java` | ArchUnit 架构约束测试 |
| `common/architecture/package-info.java` | 包说明文档 |

### pom.xml 变更
- `ydsz-pmis-common/pom.xml`: 添加 `archunit-junit5` 依赖（1.3.0）

### 覆盖规则
1. common 模块不能依赖业务模块
2. Controller 不能直接调用 Mapper
3. Feign Client 必须集中在 common.feign 包
4. project 不能直接访问 cronjob/message 的 Mapper
5. workflow 不能直接访问 message 的 Mapper
6. cronjob 不能直接访问 project 的 Mapper
7. 各模块之间不能存在循环依赖

```
V1.0.0_cronjob.sql
V1.0.0_message.sql
V1.0.0_workflow.sql

V1.0.0_literule.sql
```

注：废弃重复表清理、统一 DAG 引擎表、规则表迁移等架构优化已合并至各模块 DDL 中，不再使用独立增量脚本。

## 核心原则

> 每个概念在整个系统中只应有一张归属表、一套核心代码、一个 Feign 接口。
> common 层提供通用框架，各业务模块通过 SPI 扩展而非自建。
