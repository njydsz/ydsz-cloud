# 代码质量与安全规范

> 文档版本: V1.0 | 编制日期: 2026-06-30 | 最近更新: 2026-07-03
> 对标: OWASP Top 10 / 阿里巴巴安全规范 / 华为云安全红线

## 1. 测试覆盖率要求

| 层级 | 行覆盖 | 分支覆盖 | 强制 |
|------|--------|----------|------|
| 业务 Service | ≥ 70% | ≥ 60% | 强制 |
| Controller | ≥ 50% | — | 强制 |
| Mapper | — | — | 不强制（DB 集成测试覆盖） |
| Util/Helper | ≥ 80% | ≥ 70% | 强制 |
| 关键路径（支付/开票/回款） | 100% | 100% | 强制 |

## 2. SonarQube 质量门禁

CI 必须通过 SonarQube 质量门禁（Quality Gate）：

| 指标 | 阈值 | 说明 |
|------|------|------|
| 重复率 | ≤ 3% | 代码重复度 |
| 单文件复杂度 | ≤ 15 | 圈复杂度 |
| 单方法行数 | ≤ 50 | 方法行数 |
| 注释率 | ≥ 15% | 公共类/方法注释 |
| 新代码覆盖率 | ≥ 70% | 增量代码 |
| Blocker 漏洞 | 0 | 阻塞级问题 |
| Critical 漏洞 | 0 | 严重级问题 |

## 3. 安全红线

### 3.1 输入校验

- **所有** Controller 入参必须 `@Valid` + 字段级注解
- **禁止** 信任任何外部输入（HTTP Header、Cookie、Body）
- SQL：使用 MyBatis `#{}` 参数化，**禁止** `${}` 拼接
- 文件上传：限制文件类型、大小、扩展名校验

### 3.2 认证与授权

- **所有** 非登录接口必须通过 JWT 鉴权
- **所有** 业务接口必须有 `@PreAuthorize` 权限校验
- 关键操作（删除、修改金额、审批）必须有二次校验
- 越权访问：横向（数据权限）+ 纵向（功能权限）双层防护

### 3.3 数据安全

- 密码存储：BCrypt（cost ≥ 10）
- 敏感字段加密：AES-256-GCM
- 日志脱敏：手机号、身份证、银行卡、密码、Token
- 备份加密：AES-256
- 传输加密：TLS 1.2+ 强制

### 3.4 限流与防刷

- 登录接口：单 IP 5 QPS、5 次失败锁定 30 分钟
- 验证码：图形验证码 + 短信验证码
- 短信接口：60 秒内 1 次，每日 10 次上限
- 关键写接口：5 QPS 限流

### 3.5 依赖安全

- 每周执行 OWASP Dependency-Check
- Critical / High 漏洞必须修复
- 依赖锁定版本（`package-lock.json` / `dependency-lock.json`）
- 禁止使用未维护超过 1 年的依赖

## 4. 并发与锁

- 关键资源（编号生成、库存）使用 Redis 分布式锁
- 数据库更新使用乐观锁（`version` 字段）
- 幂等性：写操作必须保证可重入
- 禁止在事务内做远程调用（HTTP/MQ）

## 5. 日志安全

- **禁止** 在日志中打印：密码、Token、密钥、身份证、银行卡、CVV
- **禁止** 将日志输出到生产可访问目录
- 访问日志：保留 ≥ 6 个月
- 审计日志：保留 ≥ 1 年，不可删除、不可修改

## 6. 性能红线

- 慢 SQL：> 200ms 必须优化
- 接口响应：> 1s 必须优化
- 数据库事务：< 5s
- 文件上传：< 50MB
- 批量操作：单批 ≤ 1000 行

## 7. 注释与可读性

- 公共类/方法必须有 JavaDoc/JSDoc
- 复杂业务逻辑必须有行内注释
- TODO 格式：`// TODO <作者> <日期> <说明>`
- 禁止"魔法值"，必须抽取为常量
- 禁止"神奇缩写"：所有命名要见名知意

## 8. 代码 Review 检查清单

提交 PR 时作者自检：

- [ ] 是否符合命名规范
- [ ] 是否有重复代码
- [ ] 是否吞掉异常
- [ ] 是否有资源未关闭
- [ ] 是否有 SQL 注入风险
- [ ] 是否有敏感信息泄露
- [ ] 是否有新硬编码
- [ ] 是否有单元测试
- [ ] 是否影响性能
- [ ] 是否影响可观测性（日志/监控）

## 9. 性能测试

- 关键接口必须有压测报告（JMeter / wrk / Gatling）
- 上线前 P95 响应时间 < 500ms
- 100 并发用户下系统稳定
- 数据库连接池监控、慢查询监控

## 10. 可观测性

- 所有外部调用必须记录耗时日志
- 关键业务节点必须有 INFO 日志
- 异常必须有 ERROR 日志 + 堆栈
- 引入 Micrometer + Prometheus 指标
- 关键业务事件埋点（用户登录、项目创建、审批完成等）

## 11. 静态代码分析

- 必装：Checkstyle、PMD、SpotBugs、ESLint、Stylelint
- CI 集成 SonarQube，质量门禁失败禁止合并
- 新代码（< 30 天）必须满足：覆盖率 ≥ 70%、重复率 < 3%、无 Blocker/Critical

## 12. 第三方依赖安全

- 每周一自动跑 OWASP Dependency-Check + Snyk
- Critical / High 漏洞必须 7 天内修复
- 禁止引入 GPL / AGPL 协议依赖
- 引入新依赖必须经过 Tech Lead Review，附 LICENSE 截图

## 13. 密钥与凭证管理

| 场景 | 处理方式 |
|------|----------|
| 数据库密码 | Nacos + 环境变量双层 |
| JWT 签名密钥 | 环境变量，**禁止**入库 |
| API Key（第三方） | Nacos 加密配置 |
| 内部服务间 Token | OAuth2 Client Credentials |
| 前端 API Key | 仅公开的非敏感 Key 放在 `.env` |

> ⚠️ **禁止** 把任何生产密钥提交到 Git 仓库，CI 通过 GitLeaks + Trivy 强制扫描。
