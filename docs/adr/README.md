## ADR 模板

```markdown
# ADR-XXX: [决策标题]

## 状态
[已采纳 / 已废弃 / 已替代 / 已提议]

## 日期
YYYY-MM-DD

## 背景
[描述导致决策的背景、问题陈述、约束条件]

## 决策
[描述做出的决策及其理由]

## 替代方案
[列出考虑过的替代方案及为什么不选择它们]

## 影响
[描述决策带来的影响（正面/负面）]

## 关联
[相关的 ADR、PR、Issue 链接]
```

## 规范

1. 所有涉及以下方面的变更必须创建 ADR：
   - `ydsz-common/` 公共模块的架构变更
   - 引入或移除中间件/框架
   - 模块拆分/合并
   - 数据一致性策略变更
   - 安全策略变更

2. ADR 文件存放在 `docs/adr/` 目录，命名格式：`ADR-XXX-简短描述.md`

3. ADR 一旦标记为"已采纳"不可修改，如需变更需创建新 ADR 并将旧 ADR 标记为"已替代"

4. PR 中涉及架构变更时，必须在 PR 描述中关联对应 ADR 编号
