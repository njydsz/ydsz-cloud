# ADR-004: 分页参数设计

**状态**: 已修订 (1.5.0)  
**日期**: 2024-Q3 (初始), 2026-08 (修订)  
**决策者**: ydsz-team

## 背景

分页查询是系统中最常见的操作之一，需要统一以下行为：
1. 未传 `pageSize` 时的默认值
2. `pageSize` 过大时的上限截断
3. 注解中引用分页常量（如 `@Max(value = PageConstants.MAX_PAGE_SIZE)`）

## 决策变更 (v1.5.0)

**初始方案** (v1.0.0)：双值体系——编译期常量 `DEFAULT_PAGE_SIZE`/`MAX_PAGE_SIZE` + 运行时 volatile 覆盖值，通过 `CoreAutoConfiguration` 在启动时调用 `setMaxPageSize()`/`setDefaultPageSize()` 同步。

**修订方案** (v1.5.0)：以 `CoreProperties` 为单一数据源。

```java
// 启动时注入
PageConstants.init(coreProperties);

// 运行时读取（内部委托到 CoreProperties，未初始化时回退到默认值）
int max = PageConstants.getMaxPageSize();
```

**保留编译期常量**的原因：`PageQuery` 中的 `@Max(value = PageConstants.MAX_PAGE_SIZE)` 注解需要编译时常量。

**使用原则**：
- 注解场景：用编译期常量 `MAX_PAGE_SIZE` / `DEFAULT_PAGE_SIZE`
- 运行时逻辑：用 `getMaxPageSize()` / `getDefaultPageSize()` / `normalizePageSize()`
- 两者永不在同一上下文混用

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 仅编译期常量 | 简单 | 无法运行时配置 | 不采用 |
| 仅运行时配置 | 灵活 | 注解不能用 | 不采用 |
| 双值体系 (v1.0) | 两者兼顾 | volatile 全局可变状态 | v1.0 采用 |
| **CoreProperties 注入 (v1.5)** | **单一数据源** | **编译期常量仍需保留** | **v1.5.0 采用** |

## 后果

- 正面：消除了全局可变状态（volatile setter），数据流更清晰
- 负面：编译期常量和运行时值仍需两套，但这是 Java 注解机制的限制
