# ADR-006: 链路追踪能力接入规范

**状态**: 已采纳  
**日期**: 2026-08-04  
**决策者**: ydsz-team

## 背景

`ydsz-common-core` 的 `trace` 包提供了高性能 TraceId 生成（ThreadLocalRandom，2.5x 于 UUID）和 W3C TraceContext 支持（`traceparent` header），但全项目零外部引用——各模块各自用 `UUIDUtils.simpleUuid()` 或 `UUID.randomUUID()` 生成 traceId，导致：
1. 高性能生成器被闲置
2. W3C traceparent 标准未落地
3. 各模块 trace 实现碎片化

## 决策

### 1. 生成器统一委托 core

所有模块**禁止**直接调用 `UUIDUtils.simpleUuid()` / `UUID.randomUUID()` 生成 traceId，统一通过 core 的 `TraceIdGenerator`：

| 场景 | 推荐 API | 说明 |
|------|----------|------|
| 生成 TraceId | `TraceIdGenerator.generateTraceId()` | 32 位十六进制，ThreadLocalRandom |
| 生成 SpanId | `TraceIdGenerator.generateSpanId()` | 16 位十六进制，W3C 兼容 |
| 构建 traceparent | `TraceIdGenerator.traceparentHeader()` | W3C TraceContext 标准 |
| MDC/header 传播 | `TraceIdPropagation.traceHeaders()` | 同时输出 X-Trace-Id + traceparent |

**例外**：nonce（防重放随机数）等**密码学安全场景**必须保留 `UUID.randomUUID()` / `SecureRandom`，禁止用 ThreadLocalRandom 替代。

### 2. 分层接入方式

| 架构位置 | 接入方式 | 实施状态 |
|----------|----------|----------|
| Servlet Filter（`TraceFilter`） | 调用 `TraceIdGenerator.generateTraceId()` 生成，写入 MDC + RequestContext | ✅ 已实施 |
| util 工具（`TracerUtils`） | `generateTraceId()/generateSpanId()` 委托 core | ✅ 已实施 |
| Feign 拦截器 | 通过 `TracerUtils` 间接获得 core 生成器；W3C header 由 `TraceRequestInterceptor` 构建 | ✅ 已实施 |
| Gateway Filter（reactive） | 调用 `TraceIdGenerator.generateTraceId()` 生成并透传 | ✅ 已实施（9 个 Filter） |
| 业务模块 | 通过 `TracerUtils` 或 `TraceIdGenerator` 获取，禁止自行 UUID | 待推广 |

### 3. ContextKey 推广

新增上下文键时，必须使用 `ContextKey<T>`（core/context）而非裸字符串 key：

```java
// ✅ 推荐
public static final ContextKey<String> ORDER_NO = ContextKey.ofString("orderNo");
RequestContext.put(ORDER_NO, "ORD-2026-001");
String orderNo = RequestContext.get(ORDER_NO);

// ❌ 禁止
RequestContext.put("orderNo", "ORD-2026-001");
String orderNo = (String) RequestContext.get("orderNo");
```

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 各模块自行 UUID 生成 | 无迁移成本 | 性能低、碎片化、无法标准化 | 不采用 |
| 全项目改用 SkyWalking agent | 生态完整 | 强依赖 agent，非 agent 环境无 fallback | 保留 TracerUtils 反射集成 |
| core 统一生成 + TracerUtils 委托 | 性能与生态兼顾 | 需逐步迁移存量代码 | **采用** |

## 后果

- 正面：TraceId 生成统一走 ThreadLocalRandom 高性能路径，W3C traceparent 可在网关-服务间贯通
- 正面：`TracerUtils`（SkyWalking/MDC/span 管理）与 core 生成器解耦，各自专注职责
- 负面：存量代码若继续用 `UUIDUtils.simpleUuid()` 生成 traceId，会绕过规范（已在 gateway 9 个 Filter 完成替换）
- 检查方式：`grep -rn "traceId\s*=\s*UUIDUtils"` 应零匹配
