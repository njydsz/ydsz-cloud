## 26. Feign 远程调用规范

> **版本**：v1.0（2026-08-16 新增）  
> **适用范围**：所有使用 `ydsz-common-feign` 的跨服务 FeignClient 接口

### 26.1 核心原则：业务模块优先使用 common 模块能力

> **【强制】** 业务模块在实现跨服务 Feign 调用时，**必须优先使用 `ydsz-common-feign` 提供的公共能力**，禁止重复造轮子。

| 公共能力 | 所在模块 | 业务模块要求 |
|----------|----------|-------------|
| Feign 自动配置 | `ydsz-common-feign` | 通过 `@EnableYdszFeign` 启用，**禁止**使用原生 `@EnableFeignClients` |
| 服务名常量 | `FeignClientConstants` | FeignClient `name` 属性必须使用常量，**禁止**硬编码服务名字符串 |
| 路径常量 | `FeignClientConstants` | URL 路径必须使用常量，**禁止**硬编码路径字符串 |
| HTTP 连接池/超时 | `ydsz.feign.*` 配置项 | 通过 `application.yml` 调整，**禁止**自建 `Feign.Builder` |
| 分布式跟踪 | `FeignRequestInterceptor`（traceparent 注入） | 自动生效，**禁止**手动拼接 TraceId Header |
| 服务降级统一错误码 | `FeignClientConstants.FEIGN_SERVICE_UNAVAILABLE` | Fallback 必须返回此错误码，**禁止**返回 `success(null)` / `success(emptyList)` |
| ID→名称富化 | `NameAssembler` 接口 | 禁止自建同类批量查询逻辑 |

### 26.2 FeignClient 注解规范

> **【强制】** `@FeignClient` 的 `name` 属性必须使用 `FeignClientConstants` 中定义的常量。

```java
// ✅ 正确
@FeignClient(name = FeignClientConstants.WORKFLOW, contextId = "workflowClient",
        fallbackFactory = WorkflowClientFallback.class)

// ❌ 错误 — 硬编码服务名
@FeignClient(name = "ydsz-workflow", contextId = "workflowClient")
```

> **【强制】** `@PostMapping` / `@GetMapping` 等路径必须使用 `FeignClientConstants` 中的路径常量。

```java
// ✅ 正确
@PostMapping(FeignClientConstants.WORKFLOW_PATH_START)
BaseResponse<String> startProcess(@RequestBody Map<String, Object> body);

// ❌ 错误 — 硬编码路径
@PostMapping("/api/v1/workflow/engine/instance/start")
BaseResponse<String> startProcess(@RequestBody Map<String, Object> body);
```

> **【建议】** 新增服务或路径常量时，先在 `FeignClientConstants` 中定义，再使用。

### 26.3 Fallback 降级规范

> **【强制】** FeignClient 必须定义 Fallback 处理（优先使用 `FallbackFactory` 而非 `fallback` 属性），保证目标服务不可用时调用方有明确感知。

> **【强制】** Fallback 中所有返回 `BaseResponse` 的方法必须返回 `BaseResponse.error(FeignClientConstants.FEIGN_SERVICE_UNAVAILABLE, "xxx服务不可用")`，**严禁**返回以下形式：

| 禁止形式 | 问题 |
|----------|------|
| `BaseResponse.success(null)` | 调用方 `isSuccess()` 返回 true，误判为成功 |
| `BaseResponse.success(Collections.emptyList())` | 调用方误认为查询结果为空（实际是服务不可用） |
| `BaseResponse.success()` | 操作类接口误判为执行成功 |
| `BaseResponse.success(false)` | 布尔校验接口误判为校验失败（实际是服务不可用） |

```java
// ✅ 正确 — 返回统一错误码
@Override
public BaseResponse<String> trigger(String jobId) {
    log.warn("[CronjobClient] trigger 降级: jobId={}", jobId);
    return BaseResponse.error(FeignClientConstants.FEIGN_SERVICE_UNAVAILABLE, "定时任务服务不可用");
}

// ❌ 错误 — 返回 success(null)
@Override
public BaseResponse<String> trigger(String jobId) {
    return BaseResponse.success(null);
}
```

> **【强制】** Fallback 类必须使用 `@Slf4j` 注解，并在降级时输出 WARN 日志，记录降级原因和关键参数。

### 26.4 NameAssembler ID→名称富化规范

> **【强制】** 跨服务查询 ID → 名称映射（如 userId→userName、deptId→deptName）时，必须使用 `NameAssembler` 接口，**禁止**在各模块中自建同类批量查询逻辑。

```java
// ✅ 正确 — 注入 NameAssembler
@Autowired
private NameAssembler nameAssembler;

Map<String, String> userNames = nameAssembler.batchResolveNames(NameType.USER, userIds);

// ❌ 错误 — 自建 Feign 调用 + 手动拼 Map
// 应在 userinfo-api 中暴露 batch-names 接口，通过 OrgQueryClient.batchUserNames() 调用
```

> **【建议】** 提供本地数据源的业务模块应实现 `NameAssembler` 接口并标注 `@Component`，替换默认的 `NoOpNameAssembler`。

### 26.5 FeignClient 命名与 contextId 规范

> **【强制】** 同一业务模块内若存在多个调用同一服务的 FeignClient，必须通过 `contextId` 区分，避免 Bean 名称冲突。

> **【建议】** FeignClient 接口命名以 `Client` 结尾（如 `WorkflowServiceClient`），Fallback 类命名以 `Fallback` 或 `FallbackFactory` 结尾。

### 26.6 配置项使用规范

> **【强制】** Feign 相关配置（超时、重试、连接池、熔断、Bulkhead 等）必须通过 `application.yml` 的 `ydsz.feign.*` 命名空间调整，**禁止**在代码中硬编码或通过 `@Bean` 覆盖 `ydsz-common-feign` 的默认配置（确有需求时应先反馈给 common 模块负责人）。

| 常用配置项 | 默认值 | 说明 |
|-----------|--------|------|
| `ydsz.feign.timeout.connect` | 5000ms | 连接超时 |
| `ydsz.feign.timeout.read` | 10000ms | 读取超时 |
| `ydsz.feign.retry.max-attempts` | 3 | 最大重试次数 |
| `ydsz.feign.client.max-connections` | 200 | HTTP 连接池总连接数 |
| `ydsz.feign.client.max-per-route` | 50 | 单路由最大连接数 |

### 26.7 接入 Checklist

业务模块首次接入 FeignClient 时，需完成以下步骤：

- [ ] `pom.xml` 中添加 `ydsz-common-feign` 依赖
- [ ] 启动类或配置类上添加 `@EnableYdszFeign` 注解
- [ ] FeignClient 接口 `name` 属性使用 `FeignClientConstants` 常量
- [ ] 所有 URL 路径使用 `FeignClientConstants` 对应路径常量
- [ ] 定义 FallbackFactory（返回 `FEIGN_SERVICE_UNAVAILABLE` 错误码）
- [ ] 在 `application.yml` 中按需调整超时/重试配置
- [ ] 涉及 ID→名称富化的场景，使用 `NameAssembler` 接口

## 27. 领域事件规范

> **核心原则：业务模块必须优先使用 common 模块的事件发布能力，禁止重复造轮子。**
>
> 领域事件（Domain Event）是 DDD 中用于表示"已发生事实"的跨模块通信载体。
> 本规范统一事件的发布入口、类型注册、消费方式，确保模块间事件契约清晰、可追溯。

### 27.1 事件发布入口（强制）

**规则 25.1.1**：业务模块发布领域事件**必须**使用 `DomainEventPublisher` 统一门面，**禁止**直接注入 `OutboxService` 或手动构建 `OutboxMessage`。

```java
// ✅ 正确：使用统一门面
private final ObjectProvider<DomainEventPublisher> eventPublisherProvider;

public void doSomething() {
    DomainEventPublisher publisher = eventPublisherProvider.getIfAvailable();
    if (publisher != null) {
        publisher.publish(DomainEvent.builder()
                .aggregateType("Order")
                .aggregateId(order.getId())
                .eventType(DomainEventTypes.ORDER_CREATED)
                .metadata("amount", order.getAmount())
                .build());
    }
}

// ❌ 错误：直接使用 OutboxService（重复造轮子）
private final ObjectProvider<OutboxService> outboxServiceProvider;
// outboxService.appendToOutbox(OutboxMessage.builder()...)
```

**理由**：`DomainEventPublisher` 封装了可选依赖降级、异常处理、JSON 序列化逻辑。
重复实现会导致 150+ 行代码冗余、降级行为不一致、异常处理遗漏等典型问题。

**规则 25.1.2**：**废弃** `EventStore` 接口（`@Deprecated 1.8.0`）。新代码不得实现或注入该接口。
如需事件发布能力使用 `DomainEventPublisher`；如需直接写入 Outbox 使用 `OutboxService.appendToOutbox(DomainEvent)`。

### 27.2 事件类型注册（强制）

**规则 25.2.1**：所有跨模块事件类型**必须**在 `DomainEventTypes` 中注册为常量，**禁止**使用字符串字面量。

```java
// ✅ 正确：事件类型在 DomainEventTypes 集中注册
public void onProjectCreated(Project project) {
    publisher.publish(DomainEvent.builder()
            .eventType(DomainEventTypes.PROJECT_INITIATION_CREATED)  // 常量引用
            .build());
}

// ❌ 错误：使用字符串字面量（失去编译期检查）
public void onProjectCreated(Project project) {
    publishEvent("PROJECT_INITIATION_CREATED", ...);  // 字符串硬编码
}
```

**规则 25.2.2**：`DomainEventTypes` 遵循"活类型原则"——仅注册有实际发布方或消费方的事件类型。
无头事件类型（定义但无人使用）必须在代码清理时移除，避免注册表膨胀导致认知负担。

**规则 25.2.3**：命名格式 `{MODULE}_ENTITY_ACTION`（如 `ORDER_CREATED`、`USER_DISABLED`），使用过去时或完成时语态。
每个常量 Javadoc 必须注明发布方模块与消费方模块。

### 27.3 事件消费方式（强制）

**规则 25.3.1**：消费 Outbox 事件时必须使用 `@EventListener(condition = "...")` SpEL 引用 `DomainEventTypes` 常量：

```java
// ✅ 正确：SpEL 引用常量
@Async
@EventListener(condition = "#message.eventType == T(com.njydsz.common.event.api.DomainEventTypes).FLOW_INSTANCE_APPROVED")
public void onFlowApproved(OutboxMessage message) { ... }

// ❌ 错误：字符串硬编码条件
@EventListener(condition = "#message.eventType == 'FLOW_INSTANCE_APPROVED'")
public void onFlowApproved(OutboxMessage message) { ... }
```
