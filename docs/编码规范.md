## 1. 源代码风格规范

### 1.1 字符编码与换行符

| 规则 | 要求 |
|------|------|
| 字符编码 | 所有源文件必须使用 **UTF-8** 编码 |
| 换行符 | **Unix 换行符（LF）**，禁止使用 Windows 换行符（CRLF） |
| BOM 文件头 | 禁止（UTF-8 无 BOM） |
| 文件末尾 | 必须保留一个空行（trailing newline） |

### 1.2 缩进与空格

| 规则 | 要求 |
|------|------|
| 缩进单位 | 4 个空格，**禁止使用 Tab 字符（\\t）** |
| 最大行宽 | 120 字符。超过时必须换行，续行缩进 8 字符（相对于首行） |
| 禁止尾部空白 | 行尾不得包含任何空白字符（space / tab） |

### 1.3 大括号风格

采用 **K&R 风格（左大括号不换行）**，与 Google Java Style 一致：

```java
// ✅ 正确
if (condition) {
    doSomething();
} else {
    doOther();
}

// ❌ 错误 — 左大括号换行
if (condition)
{
    doSomething();
}
```

**空块可写成 `{}`**（不需要换行），但 `if (cond) ;` 形式的空语句块**禁止**。

### 1.4 空行规则

| 位置 | 规则 |
|------|------|
| 类/接口的第一个成员前 | **不加**空行 |
| 类/接口的最后一个成员后 | **不加**空行（直接 `}`） |
| 方法与方法之间 | **必须**以空行分隔 |
| 同一方法内的逻辑段 | 可用单一空行分隔，但**禁止连续多个空行** |

### 1.5 源文件结构顺序

```java
package 声明

import 声明              // 按 3.1 节规则排序

/**
 * 类 Javadoc 注释
 */
public class Example {
    
    // 1. static final 常量
    // 2. static 变量
    // 3. 实例变量
    // 4. 构造方法
    // 5. 静态方法
    // 6. 实例方法（按可见性 / 功能分组）
    // 7. 重写方法（@Override 集中放）
    // 8. 内部类 / 接口
}
```

## 2. 命名规范

### 2.1 命名总则

| 规则 | 要求 |
|------|------|
| 字符集 | ASCII 字母、数字、下划线；禁止中文拼音混合、禁止拼音首字母缩写 |
| 命名风格 | 严格遵循驼峰命名，禁止下划线命名（常量除外） |
| 自解释性 | 命名必须"见名知意"，禁止 `a`、`b`、`tmp`、`data` 等无意义命名 |
| 正词法 | 避免否定命名（`isNotEnabled` → 重构逻辑方向）；布尔变量使用 `has`/`is`/`can` 前缀 |
| 分布式 ID | 字段名统一使用 `id`，禁止使用 `uid`、`userId` 混用 |

### 2.2 各元素命名规则

| 元素 | 规范 | 示例 |
|------|------|------|
| 类名 | UpperCamelCase，名词或名词短语 | `UserService`、`OrderDTO` |
| 方法名 | lowerCamelCase，动词或动宾短语 | `findUserById()`、`save()` |
| 变量名 | lowerCamelCase | `userName`、`orderList` |
| 常量名 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT`、`DEFAULT_TIMEOUT` |
| 包名 | 全小写，点分隔，单数形式 | `com.njydsz.common.util` |
| 异常类 | 以 `Exception` 结尾 | `BusinessException` |
| 抽象类 | 以 `Abstract` 或 `Base` 开头 | `AbstractEntity`、`BaseResponse` |
| 接口 | 形容词/名词，不加 `I` 前缀 | `Serializable`、`UserService` |
| 测试类 | 以 `Test` 结尾 | `UserServiceTest` |
| 测试方法 | `test_被测场景_期望行为` | `test_findUserById_notFound_throwException` |

### 2.3 命名反例

```java
// ❌ 错误
int d;                    // 无意义
String getPingJiaByName(); // 拼音混合
boolean flag;             // 语义不清
final int max_count = 10; // 下划线命名

// ✅ 正确
int elapsedDays;
String getCommentByName();
boolean enabled;
final int MAX_COUNT = 10;
```

## 3. Import 导入规范

### 3.1 核心红线：禁止行内全限定名（FQN）

> **【强制】** 所有类型引用必须通过文件顶部的 `import` 语句声明，**严禁在代码体中使用全限定类名（Fully Qualified Name）**。

```java
// ✅ 正确 — 顶部 import，代码体使用简单名
import org.apache.ibatis.io.Resources;

public class SqlParseContext {
    private static final ThreadLocal<String> CACHED_SQL =
            new Resources.NamedThreadLocal<>("SqlParseContext.CachedSql");
}

// ❌ 错误 — 代码体中使用全限定名
public class SqlParseContext {
    private static final ThreadLocal<String> CACHED_SQL =
            new org.apache.ibatis.io.Resources.NamedThreadLocal<>("SqlParseContext.CachedSql");
}
```

**正例参考**：`org.apache.ibatis.io.Resources.NamedThreadLocal` 必须通过 `import org.apache.ibatis.io.Resources` 引入后使用 `Resources.NamedThreadLocal` 形式。

### 3.2 禁止通配符 import

> **【强制】** 禁止使用 `import xxx.*` 通配符导入。每个类型必须显式 import。

```java
// ❌ 错误
import org.springframework.beans.factory.*;
import java.util.*;

// ✅ 正确
import org.springframework.beans.factory.BeanFactory;
import org.springframework.beans.factory.ListableBeanFactory;
import java.util.List;
import java.util.Map;
```

### 3.3 import 排序与分组

import 语句按以下顺序排列，组间以**单个空行**分隔：

| 顺序 | 分组 | 示例 |
|------|------|------|
| 第 1 组 | `java.*` / `javax.*` | `java.util.List`、`javax.crypto.Cipher` |
| 第 2 组 | 第三方库（按字母序） | `org.springframework.*`、`com.google.common.*` |
| 第 3 组 | 公司内部包 | `com.njydsz.common.*` |
| 第 4 组 | 静态导入（单独一组） | `import static org.junit.jupiter.api.Assertions.*` |

**注意**：第 1 组和第 2 组之间、第 2 组和第 3 组之间必须有空行分隔。

```java
// ✅ 正确示例
import java.util.List;
import java.util.Map;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import com.njydsz.common.core.response.BaseResponse;

import lombok.extern.slf4j.Slf4j;
```

### 3.4 名称冲突处理

当两个同名类必须同时使用时，**仅对冲突的类使用全限定名**，其余仍正常 import：

```java
// ✅ 正确 — 名称冲突时的处理方式
import com.obs.services.model.ObjectMetadata;  // 正常 import 其中一个

public class FileStorage {
    public void upload() {
        // 冲突的另一个使用全限定名
        com.qcloud.cos.model.ObjectMetadata cosMeta = 
                new com.qcloud.cos.model.ObjectMetadata();
    }
}
```

**注意**：上述情况仅在名称冲突时允许，且必须在行末添加注释 `// FQN-OK: name conflict with Xxx` 说明原因。

### 3.5 未使用的 import

> **【强制】** 禁止保留未使用的 import 语句。IDE 应开启 "Optimize Imports" 自动清理。

## 4. 注释与 Javadoc 规范

### 4.1 类 Javadoc

每个公共类/接口必须有 Javadoc，包含以下标签（按顺序）：

```java
/**
 * 用户服务实现类
 *
 * <p>提供用户 CRUD 操作，支持多租户隔离。
 *
 * @author ydsz-team
 * @since 1.0.0
 */
public class UserServiceImpl implements UserService {
```

**标签说明**：
- `@author`：固定为 `ydsz-team`（团队项目不标注个人）
- `@since`：引入该类的版本号，遵循语义化版本
- `@see`：交叉引用时使用，格式为 `#方法名` 或 `包名.类名`
- `@deprecated`：标记废弃类，说明替代方案与删除版本

### 4.2 方法 Javadoc

| 方法可见性 | Javadoc 要求 |
|-----------|-------------|
| `public` | 必须有完整 Javadoc（描述 + `@param` + `@return` + `@throws`） |
| `protected` | 建议有 Javadoc |
| `package-private` / `private` | 简单方法可省略，复杂逻辑建议有行内注释 |

```java
/**
 * 根据用户 ID 查询用户信息
 *
 * <p>先从 Redis 缓存读取，缓存未命中时查询数据库并回填缓存。
 *
 * @param userId 用户 ID，必须大于 0
 * @return 用户信息，包含基本信息与角色列表
 * @throws IllegalArgumentException 当 userId 小于等于 0 时抛出
 * @throws UserNotFoundException    当用户不存在时抛出
 */
public UserDTO findById(Long userId) {
```

### 4.3 行内注释

```java
// ✅ 正确 — 解释"为什么"而非"是什么"
// 使用 NamedThreadLocal 避免 ThreadLocal 在 Tomcat 线程池复用场景下的内存泄漏
private static final ThreadLocal<String> CACHED_SQL = ...;

// ❌ 错误 — 废话注释，重复代码含义
// 将 name 赋值给 this.name
this.name = name;
```

### 4.4 TODO / FIXME 标记

```java
// TODO: 2026-08-20 待接入分布式锁（@zhangsan）
// FIXME: 高并发下存在竞态条件，需改为 CAS 操作
```

格式：`标记类型: 完成日期 描述（@负责人）`

## 5. 类与接口设计规范

### 5.1 类成员可见性

> **【强制】** 严格遵循最小可见性原则：
> - 字段默认 `private`，通过 getter/setter 访问
> - 仅在性能敏感场景或不可变对象中使用 `public final`
> - 禁止 `public` 非 `final` 字段

### 5.2 不可变类

```java
// ✅ 推荐 — 不可变对象
public final class Money {
    private final BigDecimal amount;
    private final String currency;
    
    public Money(BigDecimal amount, String currency) {
        this.amount = amount;
        this.currency = currency;
    }
    
    // 无 setter，仅 getter
    public BigDecimal getAmount() { return amount; }
    public String getCurrency() { return currency; }
}
```

### 5.3 构造方法

| 规则 | 要求 |
|------|------|
| 工具类 | 私有构造方法 + `throw new AssertionError()` |
| 单例 | 枚举实现或静态内部类 |
| 多参数 | 使用 Builder 模式（Lombok `@Builder`） |
| 依赖注入 | 构造方法注入优于字段注入 |

### 5.4 方法设计

| 规则 | 要求 |
|------|------|
| 方法行数 | 单方法不超过 **80 行**（不含空行与注释） |
| 方法参数 | 不超过 **5 个**，超过时封装为 DTO/VO |
| 返回值 | 禁止返回 `null` 集合（返回空集合）；禁止返回 `null` 对象（使用 `Optional`） |
| 方法职责 | 单一职责，一个方法只做一件事 |

### 5.5 重写方法

> **【强制】** 所有重写方法必须标注 `@Override` 注解。

## 6. 异常处理规范

### 6.1 异常分类

| 异常类型 | 使用场景 | 示例 |
|---------|---------|------|
| `BusinessException` | 业务规则校验失败 | 用户余额不足、权限不足 |
| `SystemException` | 系统级错误 | 数据库连接失败、外部服务不可用 |
| `IllegalArgumentException` | 参数非法 | 必填参数为空、格式错误 |
| `IllegalStateException` | 状态不允许 | 订单已支付不允许取消 |

### 6.2 异常处理规则

> **【强制】** 禁止捕获 `Exception` / `Throwable` 后不处理（空 catch 块）。

```java
// ❌ 错误 — 吞掉异常
try {
    doSomething();
} catch (Exception e) {
    // 什么都不做
}

// ✅ 正确 — 至少记录日志
try {
    doSomething();
} catch (BusinessException e) {
    log.warn("业务异常: {}", e.getMessage());
    throw e;
} catch (Exception e) {
    log.error("系统异常", e);
    throw new SystemException("操作失败", e);
}
```

> **【强制】** 异常信息必须包含上下文（参数值、业务 ID 等），便于排查。

```java
// ✅ 正确
throw new BusinessException("用户[%s]余额不足，当前余额：%d", userId, balance);
```

### 6.3 自定义异常

- 继承 `RuntimeException`（业务异常）或 `Exception`（系统异常）
- 提供带 `message` 和 `cause` 的构造方法
- 禁止暴露敏感信息（密码、密钥、Token 等）

## 7. 日志规范

### 7.1 日志框架

| 规则 | 要求 |
|------|------|
| 日志门面 | SLF4J（`@Slf4j`） |
| 日志实现 | Logback |
| 日志格式 | JSON 格式输出（Logstash Encoder） |
| 占位符 | 使用 `{}` 占位，禁止字符串拼接 |

```java
// ✅ 正确
log.info("用户[{}]登录成功，IP={}", username, ip);

// ❌ 错误
log.info("用户[" + username + "]登录成功，IP=" + ip);
```

### 7.2 日志级别使用

| 级别 | 使用场景 |
|------|---------|
| `ERROR` | 系统异常、需要人工介入的错误 |
| `WARN` | 可恢复异常、降级逻辑触发、配置缺失 |
| `INFO` | 关键业务流程节点（登录、下单、支付） |
| `DEBUG` | 开发调试信息（生产默认关闭） |
| `TRACE` | 最细粒度信息（SQL 参数、HTTP 请求体） |

### 7.3 日志安全

> **【强制】** 禁止打印敏感信息：密码、Token、密钥、身份证号、手机号（需脱敏）。

```java
// ✅ 正确 — 脱敏后打印
log.info("用户[{}]修改密码", username);

// ❌ 错误 — 明文打印敏感信息
log.info("用户[{}]修改密码，新密码={}", username, newPassword);
```

## 8. 并发规范

### 8.1 线程安全

| 规则 | 要求 |
|------|------|
| 共享变量 | 必须使用 `volatile`、`AtomicXxx` 或同步机制 |
| 单例 | 使用枚举或静态内部类实现，禁止双重检查锁 |
| 线程池 | 必须使用 `ThreadPoolExecutor` 显式创建，禁止使用 `Executors` |
| ThreadLocal | 必须在 `finally` 块中调用 `remove()` 清理 |

### 8.2 锁规范

```java
// ✅ 正确 — 使用 NamedThreadLocal 避免泄漏
private static final ThreadLocal<Connection> CONNECTION_HOLDER =
        new NamedThreadLocal<>("DB Connection") {
            @Override
            protected Connection initialValue() {
                return dataSource.getConnection();
            }
        };

// ✅ 正确 — finally 清理
try {
    threadLocal.set(value);
    doWork();
} finally {
    threadLocal.remove();
}
```

### 8.3 原子操作

优先使用 `java.util.concurrent` 包下的原子类，避免 `synchronized`：

```java
// ✅ 推荐
private final AtomicLong counter = new AtomicLong(0);
long next = counter.incrementAndGet();

// ❌ 避免
private long counter = 0;
private synchronized long next() {
    return ++counter;
}
```

## 9. 集合与数据结构规范

### 9.1 集合初始化

> **【强制】** 集合初始化时必须指定初始容量（已知大小时）。

```java
// ✅ 正确
List<String> list = new ArrayList<>(16);
Map<String, User> map = new HashMap<>(32);

// ❌ 错误 — 使用默认容量，频繁扩容
List<String> list = new ArrayList<>();
```

### 9.2 集合返回值

> **【强制】** 方法返回集合类型时，禁止返回 `null`，必须返回空集合。

```java
// ✅ 正确
public List<User> findUsers() {
    if (noData) {
        return Collections.emptyList();
    }
    return userList;
}
```

### 9.3 遍历与 Stream

| 场景 | 推荐方式 |
|------|---------|
| 简单遍历 | `for-each` 循环 |
| 过滤/映射/聚合 | Stream API |
| 并行流 | 仅在数据量大（>10000）且无状态时使用 `parallelStream()` |
| 修改外部变量 | 禁止在 lambda 中修改外部非 final 变量 |

## 10. 安全规范

### 10.1 输入校验

> **【强制】** 所有外部输入（HTTP 参数、RPC 参数、消息体）必须进行参数校验。

```java
// ✅ 正确 — 使用 JSR-380 Bean Validation
public void createUser(@Valid CreateUserRequest request) {
    // ...
}

// DTO 中使用注解
public class CreateUserRequest {
    @NotBlank(message = "用户名不能为空")
    @Size(min = 2, max = 32)
    private String username;
    
    @Email(message = "邮箱格式不正确")
    private String email;
}
```

### 10.2 敏感数据处理

| 数据类型 | 处理方式 |
|---------|---------|
| 密码 | BCrypt 哈希存储，禁止 MD5/SHA1 |
| 手机号/身份证 | 脱敏显示（`138****1234`） |
| Token/密钥 | 禁止日志打印，禁止 URL 参数传递 |
| 数据库连接串 | 加密存储（ydsz-common-config） |

### 10.3 SQL 注入防护

> **【强制】** 禁止拼接 SQL 字符串，必须使用参数化查询（PreparedStatement / MyBatis `#{}`）。

```java
// ❌ 错误 — SQL 注入风险
String sql = "SELECT * FROM user WHERE name = '" + name + "'";

// ✅ 正确 — 参数化查询
String sql = "SELECT * FROM user WHERE name = #{name}";
```

## 11. 性能规范

### 11.1 资源管理

> **【强制】** 所有 IO 资源（InputStream、Connection、Reader）必须使用 try-with-resources 自动关闭。

```java
// ✅ 正确
try (InputStream is = Files.newInputStream(path)) {
    // 使用 is
}

// ❌ 错误 — 手动 close 容易遗漏
InputStream is = Files.newInputStream(path);
// 使用 is
is.close();
```

### 11.2 字符串拼接

| 场景 | 推荐方式 |
|------|---------|
| 单线程大量拼接 | `StringBuilder` |
| 多线程 | `StringBuffer` |
| 简单拼接（<5 次） | `+` 运算符（编译器自动优化） |
| 格式化 | `String.format()` 或 `MessageFormat` |

### 11.3 对象创建

- 避免在循环内创建不必要的对象
- 优先使用对象池（数据库连接池、线程池）
- 大对象（>1MB）避免频繁创建

## 12. 模块依赖规范

### 12.1 依赖方向

```
web → server → domain ← infra
                ↑
               api（独立对外）
```

> **【强制】** 依赖方向必须单向，禁止反向依赖。

### 12.2 ydsz-common 模块层级

| 层级 | 模块 | 说明 |
|------|------|------|
| L1 | `ydsz-common-core` | 统一响应、TraceId、特性开关 |
| L2 | `ydsz-common-util`、`ydsz-common-json` | 工具类、JSON 引擎 |
| L3 | `ydsz-common-domain`、`ydsz-common-exception` | DDD 基类、统一异常 |
| L4 | `ydsz-common-jdbc`、`ydsz-common-redis`、`ydsz-common-lock` 等 | 基础设施增强 |
| L5 | `ydsz-common-auth`、`ydsz-common-safe`、`ydsz-common-feign` 等 | 业务能力模块 |
| L6 | `ydsz-common-base`、`ydsz-common-web`、`ydsz-common-app` | 应用基座 |

> **【强制】** 高层模块可以依赖低层模块，反之禁止。

### 12.3 第三方库使用规范

> **【强制】** 业务代码禁止直接 import 第三方 JSON 库（Jackson / Fastjson / Gson / org.json），必须统一使用 `ydszz-common-json`。

### A.1 行内导入（本文档核心红线）

```java
// ❌ 错误示例 1
org.springframework.context.expression.MapAccessor mapAccessor = 
        new org.springframework.context.expression.MapAccessor();

        (org.bouncycastle.jcajce.provider.asymmetric.ec.BCECPublicKey) publicKey;

// ❌ 错误示例 4
new org.springframework.cloud.loadbalancer.core.DiscoveryClientServiceInstanceListSupplier(...);

import org.springframework.context.expression.MapAccessor;

MapAccessor mapAccessor = new MapAccessor();
```

### A.2 命名违规

```java
// ❌ 错误
int D;                    // 单字符
String getYongHuMing();   // 拼音
boolean isnotopen;        // 否定 + 大小写混乱

// ✅ 正确
int elapsedDays;
String getUsername();
boolean isOpen;
```

### A.3 异常处理违规

```java
// ❌ 错误 — 吞异常
try {
    doWork();
} catch (Exception e) {}

// ❌ 错误 — 无上下文
throw new BusinessException("操作失败");

// ✅ 正确
try {
    doWork();
} catch (Exception e) {
    log.error("执行工作流失败, workflowId={}", workflowId, e);
    throw new BusinessException("工作流[%s]执行失败: %s", workflowId, e.getMessage(), e);
}
```
