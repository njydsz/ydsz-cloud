# 公共模块（ydsz-common-core）使用编码规范

> 适用范围：所有业务模块的 Service / Controller 层开发者
> 版本：1.0.0（2026-08-09 制定）
> 配套文档：`docs/review/ydsz-common-core-global-reference-analysis-v2.md`

---

## 0. 规范目标

1. **统一响应构造入口**：收敛到 `Results` 门面，避免 `BaseResponse.Xxx` 散落
2. **业务异常码规范化**：统一实现 `ExceptionCode` → `ResultCode` 桥接
3. **分页参数归一化**：通过 `PageQuery` + `PageConstants` 消除双轨
4. **链路追踪标准化**：W3C traceparent 兼容 + X-Request-Id 兜底
5. **上下文安全化**：推广 `ContextKey<T>` 类型安全键

## 1. API 响应构造（强制）

### ✅ 正确做法

使用 `com.njydsz.common.core.response.Results` 静态门面：

```java
// 成功（无数据）
return Results.ok();

// 成功（带数据）
return Results.ok(userDTO);

// 成功（自定义消息 + 数据）
return Results.ok("创建成功", userDTO);

// 分页（强类型信封）
return Results.page(total, pageNum, pageSize, records);

// 失败（标准错误码）
return Results.fail(BaseResultCode.BAD_REQUEST);

// 失败（自定义业务错误码）
return Results.fail(SystemResultCode.CONFIG_NOT_FOUND);

// 失败（错误码 + 自定义消息）
return Results.fail(BaseResultCode.BAD_REQUEST, "手机号格式错误");
```

### ❌ 反例（禁止新代码使用）

```java
// 禁止：直接调用 BaseResponse 工厂
return BaseResponse.success(data);
return BaseResponse.error(BaseResultCode.BAD_REQUEST);
return BaseResponse.successPage(total, pageNum, pageSize, records);

// 禁止：直接 new 响应对象
return new BaseResponse<>(200, "ok", data);
return new PageResult<>();
```

### 🔄 迁移指南

存量代码按以下模式批量替换（正则）：

| 旧模式 | 新模式 |
|---|---|
| `BaseResponse.success()` | `Results.ok()` |
| `BaseResponse.success(data)` | `Results.ok(data)` |
| `BaseResponse.success(msg, data)` | `Results.ok(msg, data)` |
| `BaseResponse.error()` | `Results.fail()` |
| `BaseResponse.error(msg)` | `Results.fail(msg)` |
| `BaseResponse.error(code)` | `Results.fail(code)` |

IDEAs 批量替换路径：
1. Edit → Find → Replace in Path
2. 启用 Regex
3. 替换后逐文件 review

## 2. 业务异常码（强制）

### ✅ 正确做法

在所有业务域定义异常码时，实现 `ExceptionCode` 接口（间接实现 `ResultCode`）：

```java
package com.njydsz.订单.domain.enums;

import com.njydsz.common.exception.enums.ExceptionCode;
import lombok.Getter;

/**
 * 订单模块异常码（编码区间：B50001-B50099）
 *
 * <p>实现 {@link ExceptionCode} 接口，获得 i18n、HTTP 状态码、异常分类能力。
 */
@Getter
public enum OrderResultCode implements ExceptionCode {

    // 订单资源类
    ORDER_NOT_FOUND("B50001", "order.not.found", 404),
    ORDER_ALREADY_CANCELED("B50002", "order.already.canceled"),
    ORDER_STATUS_INVALID("B50003", "order.status.invalid"),

    // 订单金额类
    ORDER_AMOUNT_MISMATCH("B50010", "order.amount.mismatch"),
    DISCOUNT_EXPIRED("B50011", "discount.expired");

    private final String code;
    private final String key;
    private final int httpStatus;

    OrderResultCode(String code, String key) {
        this(code, key, 400);
    }

    OrderResultCode(String code, String key, int httpStatus) {
        this.code = code;
        this.key = key;
        this.httpStatus = httpStatus;
    }

    // 注册到全局码表（可选，用于运行时反向查找）
    static {
        Map<String, ExceptionCode> map = new HashMap<>();
        for (OrderResultCode c : values()) {
            map.put(c.getCode(), c);
        }
        ExceptionCodeRegistry.register(map);
    }
}
```

### 在 Service 层抛出异常

```java
// 正确：业务异常
Order order = orderMapper.selectById(orderId);
if (order == null) {
    throw new BusinessException(OrderResultCode.ORDER_NOT_FOUND);
}
// BusinessException 自动携带 errorCode + httpStatus + messageKey

// 正确：系统异常（不可恢复）
try {
    paymentService.pay(order);
} catch (IOException e) {
    throw new SysException(OrderResultCode.PAYMENT_UNAVAILABLE, e);
}
```

### 在 Controller 层使用

```java
// 正确：通过 Results 门面直接返回错误码
@GetMapping("/{id}")
public BaseResponse<OrderVO> getOrder(@PathVariable Long id) {
    if (id == null || id <= 0) {
        return Results.fail(OrderResultCode.ORDER_NOT_FOUND);
    }
    return Results.ok(orderService.findById(id));
}
```

### ❌ 反例（禁止）

```java
// 禁止：返回自定义 message 而非标准错误码
return Results.fail("订单没找到");

// 禁止：未实现 ResultCode 接口的自定义枚举
public enum BadOrderCode {  // 缺少 implements ExceptionCode
    NOT_FOUND("B50001");
}

// 禁止：返回非标准响应体
return new ErrorResponse(404, "订单没找到");
```

## 3. 分页参数处理（强制）

### ✅ 正确做法

Controller 层统一定义 `PageQuery` 参数，运行时自动归一化：

```java
@GetMapping("/list")
public PageResult<UserVO> list(UserPageQuery query) {
    // query.pageNum 和 query.pageSize 已通过 JSR-303 + getEffective* 归一化
    IPage<UserVO> page = userService.page(
        new Page<>(query.getEffectivePageNum(), query.getEffectivePageSize()),
        query.toQueryWrapper()
    );
    return Results.page(page.getTotal(), query.getEffectivePageNum(),
                       query.getEffectivePageSize(), page.getRecords());
}
```

### 自定义 PageQuery 子类

```java
public class UserPageQuery extends PageQuery {
    private String username;
    private String email;
    private Integer status;

    // 继承 pageNum / pageSize，新增业务查询字段
}
```

### ❌ 反例（禁止）

```java
// 禁止：直接使用 request parameter 自行处理分页
@GetMapping("/list")
public PageResult<UserVO> list(@RequestParam(defaultValue = "1") int page,
                                @RequestParam(defaultValue = "10") int size) {
    // 缺少 JSR-303 校验和归一化
}

// 禁止：硬编码分页上限
if (pageSize > 100) {
    pageSize = 100; // 应使用 PageConstants.MAX_PAGE_SIZE 配置值
}
```

## 4. 链路追踪传播（推荐）

### ✅ 正确做法

#### 4.1 HTTP 入口（Filter 自动处理）

`TraceFilter`（common-base）已自动处理 HTTP 入站 traceId 提取/生成。业务代码无需额外处理。

#### 4.2 Feign 出站（拦截器自动处理）

`FeignRequestInterceptor`（common-feign）已通过 X-Request-Id header 自动透传 traceId。
新标准（W3C traceparent）正在通过 `TraceIdPropagation` 灰度增强。

#### 4.3 手动传播（HTTP 客户端场景）

```java
// 使用 TraceIdPropagation 工具类（新增能力）
HttpHeaders headers = new HttpHeaders();
TraceIdPropagation.traceHeadersOrCreate()
    .forEach(headers::set);
HttpEntity<String> entity = new HttpEntity<>(body, headers);
restTemplate.exchange(url, HttpMethod.POST, entity, String.class);

// 简易版
String traceId = TraceIdPropagation.currentTraceIdOrCreate();
request.setHeader("X-Trace-Id", traceId);
request.setHeader("traceparent", TraceIdGenerator.traceparentHeader(traceId, TraceIdGenerator.generateSpanId()));
```

### ❌ 反例（禁止）

```java
// 禁止：跨服务调用不携带 traceId
restTemplate.getForObject("http://order-service/orders", String.class);

// 禁止：hardcode traceId 值
request.setHeader("X-Trace-Id", "test-trace-id");

// 禁止：手动 new UUID 作为 traceId
request.setHeader("X-Trace-Id", UUID.randomUUID().toString());
```

## 5. 业务上下文使用（推荐）

### ✅ 正确做法

#### 5.1 读取常用上下文（语法糖）

```java
// 通过 RequestContext 命名存取器（推荐）
String tenantId = RequestContext.getTenantId();
String userId = RequestContext.getUserId();
String traceId = RequestContext.getTraceId();
AuthInfo authInfo = RequestContext.getAuthInfo();
```

#### 5.2 自定义上下文键（类型安全）

```java
// 1. 定义类型安全键
public final class OrderContextKeys {
    public static final ContextKey<CartInfo> CART =
        ContextKey.of("order.cart", CartInfo.class);
    public static final ContextKey<DiscountResult> DISCOUNT =
        ContextKey.of("order.discount", DiscountResult.class);
}

// 2. 写入
RequestContext.put(OrderContextKeys.CART, cartInfo);

// 3. 读取
CartInfo cart = RequestContext.get(OrderContextKeys.CART);
```

### ❌ 反例（禁止）

```java
// 禁止：字符串键 + Object 类型（无编译期类型安全）
RequestContext.put("cart", cartInfo);  // 字符串魔法值
CartInfo cart = (CartInfo) RequestContext.get("cart");  // 强转风险

// 禁止：存储大对象（影响 TTL 线程传递性能）
RequestContext.put(KEY_BIG_OBJECT, 10MB_Data);  // 应使用 RequestScoped Bean 或缓存
```

## 6. 编码检查清单（Code Review 参考）

新代码合入前 self-check：

| 检查项 | 规则 | 等级 |
|---|---|---|
| API 响应是否使用 `Results.ok / Results.fail / Results.page` | 替代 `BaseResponse.Xxx` | 必须 |
| 业务异常码是否实现 `ExceptionCode` | 带 i18n key + HTTP 状态 | 必须 |
| 分页参数是否使用 `PageQuery`（或其子类） | 带 JSR-303 校验 + 归一化 | 必须 |
| 跨服务调用是否透传 traceId | FeignTraceInterceptor 已处理 | 自动 |
| 自定义上下文是否使用 `ContextKey<T>` | 替代字符串键 | 推荐 |
| 是否使用了 `BaseResponse.success/error` | 存量可容忍，新代码必须改 | 必须 |
| 是否直接 `new BaseResponse<>()` | 禁止 | 必须 |
| Messages 资源文件是否覆盖异常码 i18n | key 与枚举一致 | 推荐 |

## 7. I18N 消息键约定

### 文件位置

```
src/main/resources/i18n/messages[_zh_CN].properties
```

### 命名约定

```properties
# 业务异常码（ExceptionCode.key） → messages_zh_CN
order.not.found=订单不存在或已删除
order.already.canceled=订单已取消，不可重复操作
order.status.invalid=当前订单状态不允许该操作

# 系统通用（BaseResultCode.name） → messages
error.BAD_REQUEST=请求参数错误
error.UNAUTHORIZED=登录状态已过期
error.FORBIDDEN=没有访问权限
error.NOT_FOUND=资源不存在
```

### I18n key 查找优先级

1. `ExceptionCode.getMessageKey()` → 查找 `<module>.properties`
2. `BaseResultCode.name()` → `error.<ENUM_NAME>` → 查找 core.properties
3. 回退：显示原始 key 字符串

## 9. FAQ

**Q1：存量代码是否需要立即迁移到 Results 门面？**
A：推荐渐进式迁移。新代码必须使用 Results，存量代码在修改相关逻辑时一并迁移，不强求一次性全量切换。

**Q2：为什么 BaseResponse 工厂方法不直接移除？**
A：向后兼容。Results 是委托层，BaseResponse 工厂保留但文档引导使用 Results。

**Q3：ExceptionCode 和 ResultCode 有什么区别？**
A：`ExceptionCode extends ResultCode`，extra 增加了 `getKey()`、`getHttpStatus()`、`getCategory()`。
新项目直接实现 `ExceptionCode` 即可，兼容所有 `ResultCode` 场景。

**Q4：是否必须注册到 ExceptionCodeRegistry？**
A：非必须。静态注册仅用于运行时反向查找（如 `ExceptionCodeRegistry.fromCode("B50001")`），不影响 i18n 和响应构造。
