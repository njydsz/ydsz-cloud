## 一、竞品分析：EasyCode 核心能力

| 维度 | EasyCode 做法 | 对 ydsz-generator 的启示 |
|------|---------------|--------------------------|
| **模板引擎** | Velocity | 同用 Velocity，可兼容其模板生态 |
| **生成粒度** | 表 → Entity/Dao/Service/Controller | 需扩展为 DDD 分层（api/domain/infra/server/web） |
| **类型映射** | 支持正则映射数据库 → Java 类型 | 当前简单，需支持枚举/自定义类型 |
| **配置管理** | 分组模式，项目间切换 | 需引入 Profile/Group 概念 |
| **多表生成** | 支持批量 | 当前已支持但需增强 |
| **文件对比** | 内置代码对比窗口 | 需增加增量合并能力 |
| **触发方式** | IDEA 插件，右键菜单 | 当前为独立 Spring Boot 应用 + REST API |

## 二、当前架构评估

### 2.1 现有模块结构

```
ydsz-generator/
├── pom.xml
└── src/main/
    ├── java/com/njydsz/generator/

    │   ├── config/

    │   │   └── VelocityConfig.java        # Velocity 引擎配置
    │   ├── controller/
    │   │   └── GeneratorController.java   # REST API 触发
    │   ├── model/
    │   │   ├── ColumnMetadata.java        # 列元数据
    │   │   └── TableMetadata.java         # 表元数据
    │   └── service/
    │       ├── CodeGeneratorService.java  # 核心生成服务
    │       ├── DbTypeConverter.java       # JDBC→Java 类型映射
    │       └── TableMetadataReader.java   # 元数据读取

        ├── application.yml

            ├── controller.vm
            ├── dto.vm

            ├── query.vm
            ├── repository.vm
            ├── repositoryImpl.vm
            ├── service.vm
            ├── serviceImpl.vm
            └── vo.vm
```

### 2.2 已具备能力

- ✅ Velocity 模板引擎集成
- ✅ JDBC 元数据读取（PostgreSQL）
- ✅ DDD 分层代码生成（domain/infra/server/web 四层）
- ✅ 审计字段自动排除（id/createdAt/createdBy/updatedAt/updatedBy/deleted/tenantId/status）
- ✅ 启动时自动生成（ApplicationRunner）
- ✅ REST API 触发增量生成
- ✅ 枚举值解析（注释格式：`状态:1=启用;0=禁用`）
- ✅ Javadoc 注释自动生成

### 2.3 当前不足

- ❌ 模板硬编码模块路径（`com.njydsz.system`），无法动态切换
- ❌ 缺少 api 层代码生成（FeignClient 接口/Assembler）
- ❌ 缺少 Mapper 层代码生成
- ❌ 缺少 MapStruct Converter 生成
- ❌ 不支持分组配置（EasyCode 核心能力）
- ❌ 无文件合并/对比功能（覆盖无提示）
- ❌ 命名规则简单，不支持自定义策略
- ❌ 无模板在线编辑/预览能力
- ❌ 不支持 XML 映射文件生成

## 四、核心设计决策

### 4.1 分组配置机制（对标 EasyCode）

```yaml
# application.yml
ydsz:
  generator:
    active-group: "dev-system"            # 激活的分组名
    groups:
      dev-system:                         # 分组配置
        module-name: system
        package-name: com.njydsz.system
        table-prefix: "ydsz_"
        output-dir: "D:/Code/open/ydsz-cloud"
        datasource:
          url: jdbc:postgresql://localhost:5432/ydsz_cloud
          username: ydsz
          password: ydsz123
          driver-class-name: org.postgresql.Driver
        table-names:
          - ydsz_sys_tenant
          - ydsz_sys_user
        template-set: "ddd-default"       # 模板集
      dev-userinfo:
        module-name: userinfo
        package-name: com.njydsz.userinfo
        # ...
```

### 4.2 命名策略模式

```java
/**
 * 命名策略接口 — 允许用户自定义各类名称的生成规则。
 */
public interface NamingStrategy {
    /** 表名 → 实体类名 */
    String toEntityName(String rawTableName, ModuleConfig config);
    /** 表名 → Repository 名 */
    String toRepositoryName(String entityName);
    /** 实体名 → Service 名 */
    String toServiceName(String entityName);
    /** 实体名 → Controller 名 */
    String toControllerName(String entityName);
    /** 列名 → Java 字段名 */
    String toFieldName(String columnName);
    /** 列名 → 读取方法名 */
    String toGetterName(String fieldName, String javaType);
    /** 列名 → 写入方法名 */
    String toSetterName(String fieldName);
}
```

**默认实现**：`DefaultNamingStrategy`  
**扩展点**：支持通过 SPI 或配置类替换。

### 4.3 模板管理策略

| 能力 | 实现方式 |
|------|----------|
| 内置模板 | classpath:/templates/ |
| 用户自定义模板 | `~/.ydsz-generator/templates/` |
| 模板热加载 | WatchService 监听变更 |
| 模板预览 | API 返回渲染后的代码（不写文件） |
| 模板集 | 分组绑定不同模板集（ddd-default/classic-simple） |

### 4.4 文件合并策略

```
文件已存在时：
├── skip     — 跳过（默认）
├── override — 全量覆盖（当前行为）
├── merge    — 智能合并（新增方法、保留自定义代码）
├── compare  — 展示差异，用户确认
```

## 九、与编码规范对齐

| 规则 ID | 规范要求 | 代码生成器落点 |
|---------|----------|----------------|
| YDIZ-DDD-005 | api 模块禁止自建 dto/vo/query | api 层模板仅生成 FeignClient + Assembler |
| YDIZ-ARCH-001 | 高层→低层单向依赖 | 模板中禁止的 import 不生成 |
| YDIZ-CODE-001 | UTF-8 无 BOM | Files.writeString 指定 UTF-8（已实现） |
| YDIZ-WARN-001 | 禁止 @SuppressWarnings | 生成的代码不含 SuppressWarnings |

## 十、总结

ydsz-generator 已完成第一代核心能力（JDBC 元数据读取 + Velocity 模板渲染），补齐以下能力后与 EasyCode 持平甚至超越：

1. **完整性**：补齐 api 层、Mapper、Converter 生成
2. **灵活性**：分组配置 + 命名策略 SPI + 模板热加载
3. **安全性**：文件合并/对比 + 预览模式
4. **工程化**：CLI 模式 + MCP 集成 + 前端代码生成

> 下一步建议优先执行 Phase 1（P0 阻断级任务），补齐 DDD 分层完整输出能力。
