# 代码注释规范（中文 · 大厂级）

目标：为 ydsz-pmis 前后端全部代码文件补充规范的中文注释，达到一线互联网大厂代码评审标准。
适用范围：后端 .java（含 DTO/Entity/VO/枚举/配置类/测试）、前端 .ts/.vue（含 api/store/components/composables/utils）。
不处理：iml/jar/properties/xml(非源码)/json(非源码)/.d.ts(必要时仅文件头)。

## 一、总原则
1. 仅新增注释，**绝不修改任何代码逻辑、变量名、签名、格式、空白**。
2. 注释讲"为什么/做什么/边界"，不翻译代码（避免 `i++; // i自增` 式废话）。
3. 中文为主，专有名词/类名/方法名保留英文；术语准确（如"幂等""最终一致""熔断"）。
4. 复杂分支、魔数、算法、并发、异常兜底必须注释说明意图与风险。
5. 已有注释不重复添加；只在缺失处补充。保持风格一致。

## 二、Java 规范
- 类/接口/枚举：声明上方 Javadoc，含：`/** 功能职责；核心设计/扩展点；@author（保留或补"系统"）；@since 日期(yyyy-MM-dd)；线程安全说明(如适用)；典型用法/注意事项 */`。
- 公共方法：Javadoc 含 功能说明、@param、@return、@throws、@see(可选)、复杂度/注意。
- 字段/常量：声明上方或行尾说明业务含义、取值范围、单位、是否为缓存/字典码。
- DTO/Entity/VO：类说明用途与对应领域；字段说明业务含义与来源。
- 枚举：类说明用途；每个枚举值说明含义。
- 复杂逻辑：行内 `//` 说明 why、分支意图、并发与异常边界。

## 三、TypeScript 规范
- 文件头：模块用途、主要职责、对外导出清单(可选)。
- 导出函数/方法：功能、参数、返回、异常/副作用、示例(可选)。
- interface/type：整体含义；字段含义。
- 常量/枚举：含义与取值。
- composables/store：状态含义、actions 副作用、getters 计算逻辑。
- 复杂逻辑：行内注释解释 why 与边界。

## 四、Vue 规范
- `<script setup>` 顶部：组件职责、props/emits 概览。
- defineProps/defineEmits：逐项说明含义、类型、是否必填、默认值。
- defineExpose：导出内容说明。
- 复杂模板逻辑/计算属性：注释说明计算意图与边界。
- 事件处理函数：功能与触发场景。

## 五、处理方式
- 优先用 Edit 在精确锚点插入注释块；小文件可整体重写(Write)但须保持代码原样。
- 每批文件数控制在 ~25-35 个，保证质量。
- 完成后汇报：处理文件数、跳过项、遗留风险。
