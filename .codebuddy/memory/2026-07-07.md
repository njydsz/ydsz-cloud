# 2026-07-07 LiteRule 规则引擎对标优化

## 任务
对标国内主流自研规则引擎，识别差距并逐项修复优化。

## 关键发现（分析阶段）
部分能力已存在实现但未装配/未接入执行路径：
- CEP 引擎（`CEPEngine`）已完整实现 TIME_WINDOW/SEQUENCE/AGGREGATE/ABSENCE 四种模式，但未在 `LiteRuleAutoConfiguration` 装配为 Bean、无 Controller、未接入规则引擎
- 画布 `ChainGraphConverter.toChain` 已实现 Graph→RuleChain 转换，但未接入 `DefaultRuleEngine.evaluate` 执行路径
- `DefaultBreakpointHook` 仅有断点增删查，SUSPEND 无真实阻塞，未装配
- `QLExpressExpressionEvaluator` 已存在，表达式引擎可插拔已具备
- `MicrometerRuleMetrics` 已完整实现，但 project 模块缺 `micrometer-registry-prometheus` 依赖
- 审批端点（approve/reject/status）已完整，但无 RBAC 权限注解

## 完成的 12 项优化
### P0（3项）
1. **P0-1 画布执行闭环**：新增 `GraphExecutionService` + `/{ruleCode}/graph/dry-run` 端点 + 前端 designer 运行仿真
2. **P0-2 CEP 接入**：`LiteRuleAutoConfiguration` 装配 `cepEngine` Bean + 新增 `CEPController` + 命中监听器接入规则引擎
3. **P0-3 断点调试**：增强 `DefaultBreakpointHook`（CountDownLatch 阻塞 + 快照）+ 装配 Bean + 新增 `BreakpointController`

### P1（4项）
4. **P1-4 冲突检测增强**：新增 DEAD_RULE / UNREACHABLE_SUBCONDITION 检测（AND 条件矛盾/冗余子句）
5. **P1-5 多租户物理隔离**：`RuleConfigProvider` 新增 `loadEnabledRulesByTenant` + `RuleConfigProviderImpl` 覆写为 SQL WHERE 隔离
6. **P1-6 Prometheus**：project pom 加 `micrometer-registry-prometheus` + Grafana 面板 JSON + 告警规则 yml
7. **P1-7 测试用例库化**：前端 index.vue 新增测试用例管理入口与对话框

### P2（5项）
8. **P2-8 表达式求值预览**：`ExpressionValidationService.previewEvaluate` + `ExpressionPreviewResult` + `/expression-preview` 端点
9. **P2-9 脚本真沙箱**：`ScriptRule` 三层防御（正则黑名单 + Groovy SecureASTCustomizer AST 白名单 + 反射加载兼容）
10. **P2-10 性能优化**：`DefaultRuleEngine.register` 改为二分插入保序（O(n) 替代 O(n log n) 全量sort）+ JMH 基准测试
11. **P2-11 GitOps**：`/export.yaml` YAML 导出端点 + `deploy/docs/literule-gitops.md` 工作流文档
12. **P2-12 RBAC**：`RuleAdminController` 关键写操作加 `@PrePermission`（save/toggle/delete/status/approve）+ `deploy/docs/literule-rbac.md` 权限编码文档

## 关键文件
- 新增后端：`GraphExecutionService`、`CEPController`、`BreakpointController`、`ExpressionPreviewResult`、`RuleEngineBenchmark`
- 修改核心：`DefaultBreakpointHook`、`LiteRuleAutoConfiguration`、`RuleConflictDetector`、`RuleConfigProvider(Impl)`、`ScriptRule`、`DefaultRuleEngine`、`ExpressionValidationService`、`RuleAdminController`
- 前端：`designer.vue`、`index.vue`、`api/execution/rule-engine/index.ts`
- 配置/文档：project pom、Grafana 面板、Prometheus 告警、GitOps 文档、RBAC 文档

## 技术决策
- CEP/断点调试均通过 `@ConditionalOnProperty` 控制装配，默认启用但可关闭
- Groovy 沙箱用反射加载 `SecureASTCustomizer`，避免非 Groovy 环境 ClassNotFoundException
- RBAC 复用项目已有 `@PrePermission` 注解 + `PermissionAspect`，权限编码遵循 `execution:rule:<action>` 规范
- 性能优化选二分插入而非 RETE 算法（当前规模未到 RETE 收益拐点，且实现复杂度高）

# 2026-07-07 工作流引擎对标分析

## 任务
对标国内主流自研工作流引擎（钉钉/飞书/企微审批 + Warm-Flow/FlowLong/RuoYi-Flowable），识别核心能力和细节体验差距，给出优化建议。

## 关键发现
ydsz-pmis-workflow 是自研轻量级工作流引擎（Warm-Flow 风格），不依赖 Activiti/Flowable/Camunda，但兼容 BPMN 2.0 XML。整体能力已超越多数开源竞品，但与钉钉/飞书等商业产品仍有差距。

### 已有优势（竞品少有）
- BPMN 2.0 兼容 + 轻量 JSON 双模式部署 + BPMNDI 坐标
- 5 种会签（OR/SEQUENTIAL/PARALLEL/VOTE/WEIGHTED_VOTE）+ FOREACH 循环
- 前/后/并加签 + 减签 + 追加处理人 + 多节点同退 + 自由跳转白名单
- 灰度发布（USER_HASH/RANDOM/WHITELIST）+ DMN 决策表 + AI NL2Flow
- Prometheus 指标 + 效率分析 + 三方审批同步 + 历史归档按月分区

### 主要差距（59项，按优先级）
- **P0**：分布式锁缺失（GAP-43/44）、集群定时任务重复执行（GAP-45）、无可视化设计器（GAP-05）、无逐级审批节点（GAP-16/17）
- **P1**：无 Grafana 看板（GAP-33）、通知硬编码无模板（GAP-38）、无数据权限（GAP-55）、无表单字段权限（GAP-28）、无部门负责人解析（GAP-18）、无审批附件（GAP-51）、join 令牌非原子（GAP-47）
- **P2**：委派沟通记录保留、驳回快速重审、节点级催办、通知频率控制、三方双向同步、WebSocket 心跳、敏感字段脱敏、审计日志导出等

## 产出
- 对标分析报告：`workflow-benchmark-report.md`（artifact）
- 含 10 大能力域差距分析 + 59 个 GAP 编号 + 17 项优化建议（P0×4 / P1×7 / P2×12 / P3×5）+ 实施路线图

## 架构关键信息
- 模块：ydsz-pmis-backend/ydsz-pmis-workflow
- 入口：WorkflowFacade（业务统一接口，禁止业务模块直引引擎内部）
- 核心：FlowAdvancer（状态机）+ BpmnXmlParser + FlowGraphValidator + FlowDefinitionCacheService(Caffeine)
- Service 拆分：FlowTaskComplete/Query/Sign/Batch 4 个子 Service + FlowTaskSupport 共享辅助
- 24 张表：pmis_flow_definition/node/skip/instance/run_task/his_*/user/cc/audit_log/delegate_*/dmn_table/timer/event_subscription/notify_outbox/auto_trigger/third_party_*
- 表达式引擎：优先 Aviator（literule），回退 SpEL（FlowVariableStrategy）
- 灰度：FlowCanaryService.resolveEffectiveDefinition 在 start 时切流
